## 0. What 4.3 builds (the dialectic as composable stages on the existing loop)

The dialectic is **four stages on the existing graph/FSM loop** plus a terminal sink, wired as a
Test-Kit reference pathway, with the truth-bearing consequences projected **off the write path**:

```
        ┌──────────────────────── refine (Transition → "thesis") ──────────────────────┐
        ▼                                                                               │
   ThesisStage ──▶ ExperimentStage ──▶ AntithesisStage ──▶ EvaluateStage ──────────────┘
   (propose)       (calls oracle)      (adversary)         (pure-code router)
                                                                 │
                                                                 ├─ success ─▶ ConcludeStage ──┐
                                                                 ├─ abstain/stuck/over_budget ─▶  │
                                                                 │     AwaitHuman(to="conclude") ─▶│
                                                                 └─ unverifiable ─▶ Degraded(to=  │
                                                                       "conclude") ───────────────┘
     ConcludeStage discriminates arrival route from the committed routing step's result.kind
     (transition=direct, await-human=escalation, degraded=unverifiable), reads the structural verdict
     bits or the typed HumanResolution, and emits Done (→COMPLETED) only for a verified or
     human-confirmed success, else terminal Degraded(to=None) (→DEGRADED). See §2.5.
```

Truth consequences (entity-KG evidence) are written by a **separate, sweeper-shaped
verification-evidence projector** that polls committed journal steps — never inline in a stage (S1).

## 1. The stage graph (structure the `StageGraph` validator must accept)

`StageGraph` (`loop/graph.py:46-119`) validates at construction: unique names, no dangling edges,
full reachability from `entry`, and **≥1 reachable terminal** (a stage with `transitions == ()`).
A refine loop (`evaluate → thesis`) is legal *as long as a terminal stays reachable*. The dialectic
has no naturally-terminal stage (evaluate must both refine and finish), so we add an explicit
**`ConcludeStage`** sink — this also keeps every runtime `result.to` a *declared* edge (the engine's
declared-route guard + the `pathway_fingerprint` both trust `edges_from`).

| Stage | `name` | `transitions` | terminal? |
|---|---|---|---|
| ThesisStage | `"thesis"` | `("experiment",)` | no |
| ExperimentStage | `"experiment"` | `("antithesis",)` | no |
| AntithesisStage | `"antithesis"` | `("evaluate",)` | no |
| EvaluateStage | `"evaluate"` | `("thesis", "conclude")` | no |
| ConcludeStage | `"conclude"` | `()` | **yes** |

Entry = `"thesis"`. Reachability: thesis→experiment→antithesis→evaluate→{thesis, conclude}; conclude
is the reachable terminal. Every `result.to` evaluate emits (`"thesis"`, `"conclude"`) is in
`edges_from("evaluate")`. ✅ validator-clean.

**Why route success/await/degraded *through* `conclude` rather than terminating at evaluate:** a
single synthesis point produces the final `Artifact` (the answer + its honest verification status),
and `AwaitHuman(to="conclude")` lets a human resolve an escalation and then have `conclude` finalize.
`conclude` reads the last verdicts (`ctx.last_output`) + any `ctx.read_human_input` and emits `Done`.

## 2. Per-stage contracts

All inter-stage data travels as `Artifact` (the journal commits `StageResult.output`; the engine
threads **no** artifact between stages — F5). Each stage **serializes its typed contract into
`Artifact.data`** via `model_dump(mode="json")` and downstream stages **reconstruct** via
`model_validate`. Artifact `kind` is the projector's discriminator (see §5), so kinds are contractual:

- ThesisStage → `kind="thesis"`, data carries `Thesis` (`proposed_solution`, `experiment_design`,
  `verifiable_claim`). `verifiable_claim is None` is the honest abstention (4.2).
- ExperimentStage → `kind="oracle-verdict"`, data carries the oracle `Verdict` **plus** the
  `verifiable_claim` text (the subject the projector attaches evidence to).
- AntithesisStage → `kind="antithesis-verdict"`, data carries the `AntithesisVerdict` + the
  `verifiable_claim` text + `oracle_backed` provenance bit.
- EvaluateStage → no new artifact kind of its own; emits the routing `StageResult`. Its `output`
  is a small `kind="dialectic-route"` audit artifact (the `RoutingDecision.reason`, cycle index) —
  **audit only**, never read for control (S9).
- ConcludeStage → `kind="dialectic-conclusion"`, the final answer + honest verification status.

### 2.1 ThesisStage (propose)
Assembles its context (`ctx.assemble_context`), calls `ctx.model.complete`, parses a `Thesis`. On a
**refine** re-entry (cycle ≥ 2) it pulls the prior antithesis breakage via `ctx.last_output(
"antithesis")` and the prior thesis via `ctx.last_output("thesis")` and folds them into the prompt —
**quarantined** (the breakage text is model-authored). Honest abstention: if the model cannot form a
verifiable claim, it returns `Thesis(verifiable_claim=None)` (valued, not penalized — 4.2).

### 2.2 ExperimentStage (calls the oracle)
Resolves an `Oracle` from an `OracleRegistry` by `(completion_criterion, problem_type)` (exact →
wildcard → always-on `LLMJudgeOracle` fallback). Builds an `OracleFrame` from the thesis, calls
`oracle.evaluate(frame=, thesis=, ctx=)` → `Verdict`. The verdict's `source` is set by the oracle's
**structural nature** (executable → `tool`/`system`; judge → `inference`) — never model output. Stamps
the `Verdict` + `verifiable_claim` into its artifact. **The registry is injected into the stage at
construction** (the pathway author wires it), so the stage stays model-agnostic and the registry is
the single resolution authority.

### 2.3 AntithesisStage (adversary — S9 structural independence)
The adversary attacks the thesis as **untrusted adversary input**: it sees the thesis's *claims and
experiment design*, grants them **no instruction-authority**, and shares **no privileged state** with
the thesis. Independence is *no-shared-state + untrusted-marking* — **NOT** "blind to thesis
reasoning." (The artifact's free-text fields *can* carry reasoning; we mark it untrusted, we do not
pretend it is absent — the earlier "no CoT field, nothing to leak" framing was false, H2.)

**Invariant AT-INDEP (spike-asserted, H1):** the antithesis model call's assembled context is a pure
function of (i) its own fixed instructions and (ii) the thesis *artifact* fields (`proposed_solution`,
`experiment_design`, `verifiable_claim`) — nothing else. Concretely it builds a **minimal
`ContextRequest` with `query=None`** (so the memory/recall slot is skipped — `context/types.py:227-228`),
threads in **no** thesis transcript/CoT/scratchpad, and every thesis-authored string enters the prompt
**only** through `quarantine()` (S10). No shared mutable context passes thesis→antithesis (free from the
fresh-stage-instance seam — F5).

The three real isolation mechanisms (in order of load): **(1) fresh stage instance** — the engine
threads no live state between stages (F5, *primary*); **(2) minimal `ContextRequest`** — no memory
slot, no thesis transcript; **(3) `quarantine()` framing** — *defense-in-depth* on top (per
`verification/quarantine.py:9-11`, the fresh-context boundary is primary, the frame is belt-and-suspenders).
`context_policy`/`bind_context_policy` is a **budget** ceiling only (`context/types.py:182-196` —
`total_budget` + `memory`) and is **NOT** the content-isolation mechanism; the earlier draft
mis-attributed isolation to it.

- **Trajectory upgrade over tess (SIRAJ):** when the thesis artifact carries intermediate steps /
  tool calls, the antithesis challenges the **trajectory**, not just the final answer (~2–2.5×
  vulnerability coverage). v1 = a **single dialectical pair** (echo-chamber + cost rule out an
  N-agent panel now — architect-confirmed, plan §219-222).
- Emits an `AntithesisVerdict` (`BROKE`+breakage / `COULD_NOT_BREAK` / `ABSTAINED`). The cross-field
  validators (4.2) structurally forbid an incoherent verdict (BROKE w/o breakage; confidence≥1.0 w/o
  `oracle_backed`).
- **Invariant OB-PROV (spike-asserted, H4 — closes the laundering hole):** `oracle_backed` is set by
  the stage **solely from an oracle call the stage itself makes** — **NEVER** from parsed model output.
  In v1 the adversary is a *model* (no executable oracle call), so `oracle_backed` is **hardwired
  `False`**. Belt-and-suspenders: the stage parses the model into an intermediate shape
  (`disposition`/`breakage`/`confidence`) that has **no `oracle_backed` field at all**, then constructs
  the `AntithesisVerdict` itself — the model has **no channel** to write the bit (mirrors the
  `Verdict.source` discipline, `contracts.py:85-95`). Without this, a model self-report (`oracle_backed=
  true`, confidence<1.0 passes the validators) launders into `confirmed` truth evidence via the §6
  adapter — the exact S9 violation F2 exists to close.

### 2.4 EvaluateStage (pure-code router — the heart)
Reads the current oracle `Verdict` (`ctx.last_output("experiment")`) and `AntithesisVerdict`
(`ctx.last_output("antithesis")`), derives the loop accumulator (§3) from the journal, and routes via
the **pure** `route_dialectic(...)` decision (§4). Constructs the actual `StageResult` from the
returned disposition — reusing `route_failure` (4.2) for the failure-side mapping. Emits an audit
`dialectic-route` artifact. **No model call** (S1-adjacent: evaluate is pure control).

**LANDMINE (red-team Point 6 — impl invariant):** the **success** outcome MUST be wrapped as
`Transition(to="conclude")` (kind `"transition"`), **never** routed through `route_failure` → its
`"done"` disposition → a `Done`. `route_failure`'s `RoutingDecision.disposition` is
`Literal["done","await-human","degraded"]` with **no `"transition"`** (`honest_failure.py:262,283`); if
evaluate naively maps success→`"done"`→`Done`, the engine **COMPLETES the run at evaluate**
(`engine.py:855-859`), ConcludeStage never runs, and the entire H5 single-synthesis-point + conclude
re-gate is **bypassed**. (Contained — §4 rule 6 keeps judge-only passes out of the success outcome, so
this would only mis-fire on a genuine executable pass — but it loses H5.) Spike **8a** must assert the
committed evaluate step's `result.kind == "transition"`, not merely the run status.

### 2.5 ConcludeStage (terminal sink — chooses its own terminal disposition, H5)
Conclude discriminates its **arrival route from committed control flow**, not human-row presence (the
previous "presence of `ctx.read_human_input`" discriminator was non-implementable — `read_human_input`
is a step-*indexed* point lookup with no enumeration API, and human-answer rows are durable/accumulate
— architect-corrected). It loads `run = await ctx.journal.load_run(ctx.run_id)` and scans
`reversed(run.steps)` for the **routing step**: the most-recent step whose
`getattr(result, "to", None) == "conclude"`. This step is **unique** — `"conclude"` is reachable only
from `evaluate`, and an `AwaitHuman(to="conclude")` is terminal-on-resume (the refine loop only
re-enters via `Transition(to="thesis")`), so no earlier cycle ever leaves a stale `to=="conclude"`
row. Its `result.kind` selects the gate (and, for the human route, *its* `step_index` is exactly the
index to pass to `read_human_input` — derived, never hardcoded):

- **`kind == "transition"`** (direct success route): emit **`Done`** (→COMPLETED) **iff** the §4-rule-4
  executable-oracle predicate holds on the **structural** verdict bits read from the **cycle-matched**
  committed experiment/antithesis steps — the verdicts of the **thesis-bounded cycle the routing step
  belongs to** (via the pure `cycle_verdicts(run, routing_step.step_index)` helper, NOT the global
  most-recent of each kind — an architect-ruled hardening that fail-closes a cross-cycle pair; see §12)
  (`Verdict.holds ∧ valid_check ∧ is_executable ∧ AntithesisDisposition.COULD_NOT_BREAK` — never
  `confidence` floats, never reasoning text). Conclude may **NOT** upgrade a model-judge pass.
  Otherwise terminal `Degraded(to=None)`.
- **`kind == "degraded"`** (degraded/unverifiable route): terminal **`Degraded(to=None)`**
  unconditionally — conclude does not re-examine verdicts.
- **`kind == "await-human"`** (escalation route): read `answer = await ctx.read_human_input(
  routing_step.step_index)` and validate `HumanResolution.model_validate(answer.data)` (a frozen
  Pydantic model in the dialectic module — `extra="forbid"`, `resolution: Literal["confirm-success",
  "decline","cannot-verify"]`; §7). **`resolution == "confirm-success"` → `Done`; any other validated
  value, a `ValidationError`, or `answer is None` → terminal `Degraded(to=None)`.** Conclude does
  **NOT** consult the executable-success predicate on this route — the escalation is **honored**, never
  overridden by a coincidentally-passing final cycle. The closed-enum validation is a *structural*
  read (S9), not free-text interpretation — it replaces the stringly `data["decision"]=="approve"`
  prior art.
- **No routing step found** (graph-invariant violation / corrupt resume): terminal `Degraded(to=None)`,
  reason `"no committed route into conclude"` — **fail-closed** (S8), never `Done` on an undefined
  arrival.

Crash/resume-correctness (S6): the discriminator is a **pure function of durable committed steps** — a
cold resume re-derives the identical route, index, and disposition with **no model re-call** (replay —
`engine.py:762`). This keeps the **single synthesis point** AND makes the epistemic outcome legible at
the **run-status** level (S8/S9). `transitions == ()` stays — both `Done` and `Degraded(to=None)` are
terminal, neither bears a `to` edge, so the declared-route guard never fires (`engine.py:832-841`).

| Dialectic outcome | routing step `kind` (`to=="conclude"`) | conclude reads | emits | `RunStatus` |
|---|---|---|---|---|
| Direct success (exec-oracle `holds∧valid_check∧is_executable` ∧ antithesis `COULD_NOT_BREAK`) | `transition` | exec-success predicate on **cycle-matched** committed verdict bits | `Done` | COMPLETED |
| Direct route, predicate fails (judge-only pass) | `transition` | predicate → false | `Degraded(to=None)` | DEGRADED |
| Await-human → `resolution=="confirm-success"` | `await-human` | `read_human_input(routing_step.step_index)` → `HumanResolution` | `Done` | COMPLETED |
| Await-human → `decline`/`cannot-verify`/unrecognized/absent | `await-human` | same, validation fails or non-success | `Degraded(to=None)` | DEGRADED |
| Unverifiable / degraded (soft failure) | `degraded` | nothing (route is decisive) | `Degraded(to=None)` | DEGRADED |
| No routing step (corrupt) | — | — | `Degraded(to=None)` | DEGRADED |

## 3. F6 — loop accumulator derived-at-read, with a hard ceiling

The refine loop's epistemic state (cycle index, breakage history, stuck-detector inputs) has **no
durable in-memory home**: a fresh stage instance after a crash-resume has zero in-process state, and
per-visit `step_index` replays the *path*, not the *accumulator* (plan §212-218). So it is
**recomputed every evaluate visit from committed steps** — mirroring the Pod 2.1 derive-at-read
posterior.

**`derive_accumulator(run_state) -> DialecticAccumulator`** (pure):
- `run_state = await ctx.journal.load_run(ctx.run_id)` (the `InMemoryJournal`/Timescale adapter
  populates `run_state.steps: tuple[StepRecord, ...]`).
- Walk `run_state.steps`, filter by `stage_name`:
  - `cycle_index` = count of committed `"antithesis"` steps. (Ordering: experiment→antithesis commit
    *before* evaluate runs, so the current cycle's antithesis is already committed when evaluate
    derives — `cycle_index` counts this cycle.)
  - `breakage_history` = the `breakage` strings from each committed antithesis step (reconstruct
    `AntithesisVerdict` from `step.result.output.data`).
  - `thesis_texts` = `proposed_solution` from each committed `"thesis"` step (for the stuck-detector).
- **Crash-correctness (the thing most likely to be silently wrong — architect R5):** the accumulator
  is a pure function of the durable committed steps, so a cold resume on a fresh `EvaluateStage`
  recomputes the *identical* accumulator with **no model re-call**. This is a headline spike assertion.

**Hard cycle ceiling:** `MAX_CYCLES = 5` (tess `MAX_ITERATIONS`). When `cycle_index >= MAX_CYCLES`,
evaluate routes `STUCK → AwaitHuman` — escalation, **not** the global `max_steps` guillotine and
**not** self-termination (S11). Lives in evaluate routing.

**Stuck-detector:** Jaccard similarity over consecutive `thesis_texts` (token sets). If the latest
thesis is ≥ `STUCK_JACCARD` (e.g. 0.92) similar to the prior one, the loop is not making progress →
`STUCK → AwaitHuman`. Pure, structural, no model call.

## 4. F2 — the honest S9 routing boundary (load-bearing redesign)

Routing is pure code, **but its inputs are not all ground truth** (plan §189-197). The antithesis
`disposition`/`confidence` are *model self-reports*; only an **executable/deterministic oracle**
verdict is S9 ground truth. The router reads **only structural bits** — never `confidence` floats,
never `reasoning`/`breakage` text:

**`route_dialectic(*, oracle: Verdict, antithesis: AntithesisVerdict, acc: DialecticAccumulator,
thesis_abstained: bool, budget_exhausted: bool) -> DialecticRoute`** (pure):

Priority order (first match wins):
1. `thesis_abstained` → `FailureOutcome.ABSTAIN` → **AwaitHuman**.
2. `budget_exhausted` → `FailureOutcome.OVER_BUDGET` → **AwaitHuman** (S11 — must not self-terminate;
   the `BudgetGuard` is the structural trigger).
3. `acc.cycle_index >= MAX_CYCLES` or stuck-detector trips → `FailureOutcome.STUCK` → **AwaitHuman**.
4. **Success (the only Done path):** `oracle.holds AND oracle.valid_check AND oracle.is_executable
   AND antithesis.disposition == COULD_NOT_BREAK` → `COULD_NOT_BREAK_AND_ORACLE_PASS` → **Done**
   (via conclude). *Note the `is_executable` gate* — see (6).
5. `oracle.valid_check is False` (no executable oracle ran / invalid check) →
   `FailureOutcome.UNVERIFIABLE` → **Degraded** (honestly incomplete).
6. **F2 boundary — model-judge cannot certify:** `oracle.holds AND oracle.valid_check AND NOT
   oracle.is_executable` (an LLM-judge "pass") → it is a *heuristic prioritizer, not a verifier*. It
   **must not by itself emit a confident "verified."** → `FailureOutcome.UNVERIFIABLE` → **Degraded**
   (honestly incomplete) — never **Done**.
7. Otherwise (antithesis `BROKE`, or executable oracle `¬holds` — a real refutation), under the
   ceiling → **refine**: `Transition(to="thesis")`.

The disposition side reuses `route_failure` (4.2) for `ABSTAIN/STUCK/OVER_BUDGET/UNVERIFIABLE/
COULD_NOT_BREAK_AND_ORACLE_PASS → {await-human, degraded, done}`. The `refine` case is a
dialectic-local 6th outcome (a `Transition`, not a failure) — `route_dialectic` returns a small union
`DialecticRoute = FailureOutcome | REFINE`.

**Run-status honesty (H5):** the `Degraded`/`AwaitHuman` routes here all carry `to="conclude"` — the
**terminal disposition** (`Done` vs. terminal `Degraded(to=None)`) is decided by **ConcludeStage**
(§2.5) from the honest verification status, so an unverifiable/degraded dialectic ends `RunStatus.
DEGRADED`, never a laundered `COMPLETED`. The router never emits a terminal result itself.

**Honest documentation requirement (plan §196, red-teamer Attack 1):** the module docstring + the
code state plainly that routing is **self-report-free only behind an executable oracle**; behind the
LLM-judge fallback, routing reads the *structural* `source=="inference"` bit to *downgrade* a judge
"pass" to honestly-incomplete — it does **not** claim general self-report-freedom.

## 5. F1 — verification-evidence projector (a DISTINCT off-path event stream)

The `EvaluateStage` does **not** write truth evidence inline (S1). A **separate, sweeper-shaped
verification-evidence projector** (`verification/evidence_projector.py`) writes the entity-KG evidence,
modeled on `runtime/projector.py` (the trial projector) — but it is a *different stream*:

- The existing `TrialProjector` hardcodes `source="system", confidence=1.0` (`projector.py:246-249`)
  and `resolve_outcome` *raises* without a `procedure_id` (`projector.py:128-138`) — it projects
  **procedure** trials, not verification verdicts. We do **not** reuse it (plan §198-204).

**Shape (mirrors `TrialProjector`):**
- Own cursor consumer key: `"verification/evidence-projector"` — its own `ProjectionCursor` so the
  journal table stays pure (S3) and the Pod 2.1 trial cursor is untouched.
- `tick()`: `committed_steps_after(cursor, limit=batch)` (single fenced commit-order read) → resolve
  each step → **`project_claims(consumer, writes, progress)`** so the evidence writes **and** the
  cursor advance commit **atomically** (S2 — no re-projection window where a crash between write and
  advance double-writes; the trial projector uses the same atomic path). Idempotent on re-projection
  (evidence keyed by `source_id = f"{run_id}:{step_index}"`; read-path dedup by `(source_id, polarity)`
  keeps the *posterior* idempotent even though physical `EvidenceEvent`s accumulate — so the spike
  asserts on the **derived posterior / `source`**, never the raw `evidence_for` count).
- **Resolution by `Artifact.kind`** (decoupled from any pathway registry):
  - `kind=="oracle-verdict"` → reconstruct `Verdict`, `record_for(verdict, role="oracle")`.
  - `kind=="antithesis-verdict"` → reconstruct `AntithesisVerdict`, adapt to `Verdict` (§6),
    `record_for(adapted, role="antithesis")`.
  - else → skip (ordinary control flow).
- For each non-`None` `VerificationRecord`: write an `EvidenceEvent` (via `make_evidence`) to the
  entity KG. **Provenance source = the verdict's `source`** (F1 — `tool`/`system` for executable,
  **`inference` for a model-judge verdict, never laundered to a confirmed `confidence=1.0`**).
  - `source_id = f"{run_id}:{step_index}"` (framework-assigned, S9 — never model output).
  - `source_authority` (required by `make_evidence`, scales the Beta weight — S3): stamped by the
    projector from the verdict's **structural** source, not the model — executable `tool`/`system`
    proof = high authority; `inference` judge = low authority. Exact values pinned at impl from the
    Pod 2.1 calibration, but the *ordering* (executable > inference) is contractual.
  - **Claim-node identity (S1 — resolved, not "confirmed at impl"):** all verdicts about **one**
    `verifiable_claim` must resolve to **one** claim node so evidence *accumulates*. So
    `claim_id = claim_id_for(subject=<normalized verifiable_claim>, predicate="verified_by",
    object_repr=<normalized verifiable_claim>)` (`knowledge/identity.py:55`) — derived **only** from the
    claim subject, **never** from per-verdict data (which would split every verdict onto its own node
    and make `add_evidence` dead code). Per-verdict identity lives in `source_id`. First evidence →
    `entity_kg.write_claim(claim, evidence=ev)`; subsequent → `entity_kg.add_evidence(claim_id, ev)`.
  - Evidence type/polarity from the `VerificationRecord`: `tool_proof"+"` / `refutation"-"` (weight
    3.0, FIRST-HAND only) / `antithesis_survival"+"` (weight 1.5, indirect).
- **Procedural-KG Beta:** `record_for` computes `procedural_outcome`, but v1 has **no procedure
  binding** for the dialectic (the stages carry no `procedure_id`). So the projector **stamps no
  procedural Beta in v1** — `stamps_procedural_beta` is honored only when a procedure binding exists
  (none yet). This keeps the Pod 2.1 projector + posterior **untouched and honest** (plan §208-210),
  exactly the goal. Recorded as a carry-forward (a future "dialectic-as-procedure" binding).

## 6. Reconciling `AntithesisVerdict` ↔ `Verdict` (the parallel-work seam)

4.0 produced `record_for(verdict: Verdict, role)`; 4.2 produced `AntithesisVerdict`. The projector
needs the antithesis step as a `Verdict` to reuse `record_for`. **Add a thin pure adapter** (in
`verification/outcome.py` — it already imports `Verdict`; importing `AntithesisVerdict` from
`honest_failure` is acyclic: `honest_failure` imports only `cost.budget`):

```
def verdict_from_antithesis(av: AntithesisVerdict) -> Verdict:
    source = "tool" if av.oracle_backed else "inference"   # oracle_backed set only by exec oracle
    if av.disposition is AntithesisDisposition.ABSTAINED:
        return Verdict(holds=False, valid_check=False, reasoning=..., source=source)
    holds = av.disposition is AntithesisDisposition.COULD_NOT_BREAK
    return Verdict(holds=holds, valid_check=True, reasoning=av.breakage or "...", source=source)
```

Faithful to `record_for`'s antithesis semantics (`outcome.py:86-90`): `COULD_NOT_BREAK` → `holds=True`
→ `antithesis_survival "+"` (epistemic `confirmed` iff executable else `inference`); `BROKE` →
`holds=False` → `record_for` returns `None` (a model-claimed break drives *refinement*, not truth
evidence — a first-hand executable break is recorded via the **oracle** role as `refutation`);
`ABSTAINED` → `valid_check=False` → `None`. No duplicated logic; the projector's inputs stay uniform
(`Verdict` + role). Adapter is unit-tested directly.

The adapter's `source = "tool" if av.oracle_backed else "inference"` is **only safe because OB-PROV**
(§2.3) guarantees `oracle_backed` was set by the stage's own oracle call, never copied from model
output. In v1 (model adversary, no executable oracle) `oracle_backed` is always `False`, so the
adapter always yields `source="inference"` → antithesis-survival evidence is epistemic `inference`,
never `confirmed`. The H4 spike (§8.7) asserts a model claiming `oracle_backed=true` cannot change this.

## 8. Spike (S12) — `tests/spike/test_pod_4_3_dialectic_spike.py`
