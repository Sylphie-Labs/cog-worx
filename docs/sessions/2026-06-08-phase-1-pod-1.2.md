## What landed

- **The exactly-once-preserving retry model.** A **failed attempt commits nothing** — only a
  success-class result (or the exhaustion `Degraded`) lands at `seq`, so the journal's
  "committed ⟺ succeeded ⟺ never re-run" stays pristine. `seq` freezes while a
  per-`(run_id, step_index)` **attempt counter** (`cogworx_step_attempts`) climbs; the journal itself
  distinguishes a retry (no committed step at `seq`) from a wait (committed `Wait` at `seq`).
- **Declarative `RetryPolicy`** (`loop/retry.py`): `max_attempts`, `backoff`, `retryable` (exception-type
  allowlist), `timeout`, `on_exhausted`, `exhausted_to`. Per-stage via an optional `retry_policy`
  attribute (engine reads `getattr(stage, "retry_policy", DEFAULT_RETRY_POLICY)` — existing stages
  unchanged). `DEFAULT_RETRY_POLICY` is opt-in (`retryable=()`), so a raising stage behaves exactly as
  pods 1.0/1.1 (S8 back-compat).
- **Engine retry/timeout arm** (`_drive`): `asyncio.wait_for(stage.run, policy.timeout)`;
  `except (TimeoutError, *policy.retryable)` → **failure-keyed** `increment_attempt`; if attempts remain,
  arm a backoff retry timer (`{run_id}:{seq}:retry:{n}`) + set **`RETRYING`** + break; on exhaustion,
  **degrade-onward** by default (commit a first-class `Degraded(to=exhausted_to)` at `seq`) or `FAILED`
  per policy. A **non-retryable** exception is **not caught** — it propagates (fail-loud); no increment,
  no timer, run left `RUNNING` (recoverable by explicit `resume`).
- **`fire_timer` generalized** to claim any parked run (CAS `<WAITING|RETRYING>→RUNNING`, then
  `cancel_timers_for_run`, then drive) — a wait re-drive advances past the committed `Wait`; a retry
  re-drive finds `read_step(seq) is None` and re-attempts at the same `seq`. The run-status CAS gives
  exactly-once **execution** even under concurrent/stale-lease retry-fire.
- **Honest provenance for control events.** Added `ProvenanceSource = "system"` (engine/control-plane,
  zero-model) and used it for the exhaustion `Degraded.output` — `"reflection"` falsely implied model
  cognition (S1 reserves it for model-heavy work). A public-API Literal addition (minor semver).

## Validation (the discipline caught a real S6 regression)

- **Spike (tests-first, mutation-resistant):** R1 retry-then-succeed (exactly one committed step at
  `seq`) · R2 durable attempt count across crash · R3 exhaustion→degraded-onward (+ R3b terminal
  DEGRADED) · R4 exhaustion→fail · R5 in-process timeout · R6 non-retryable propagates · R7 exactly-once
  execution under concurrent retry-fire · S1/S5/S6/S9/S11 invariants · default-policy back-compat.
- **Architect (pre-code)** resolved the exactly-once interaction (failed attempts don't commit;
  attempt-counter as a separate key) and confirmed in-process timeouts don't drag in the deferred reaper.
- **Red-team** found one **HIGH**: the new `exhausted_to` graph edge (added to `_edges()` for
  reachability) was **not** in `pathway_fingerprint()` (which read only declared transitions), so the
  pod-1.0D resume divergence guard was **blind** to an in-place exhaustion-route edit
  (`fp(None) == fp("close")`). **Fixed:** a single `StageGraph.edges_from()` source-of-truth (transitions
  + `exhausted_to`) now drives BOTH validation and the fingerprint; red→green test added; pre-1.2
  fingerprints byte-identical (no resume break). The retry core (attempt counting, no double-execution,
  no-commit-on-failure, fail-loud, budget bound) survived every attack.
- **CANON: COMPLIANT** (S1–S12, §3/§4); the only concern — the `"reflection"` provenance — was fixed
  with the `"system"` source above.

## Carry-forward

- **Crashed-mid-drive auto-recovery (still deferred to a future ops pod).** Pod 1.2 ships **in-process**
  timeouts only; a process that dies mid-attempt strands as `RUNNING` (recovered by explicit `resume`,
  which re-attempts with the correct journaled count — under-counts on hard crash, never over-counts, so
  never prematurely exhausts). Red-team FINDING 2: a fire-winner that crashes between the CAS→RUNNING and
  `cancel_timers_for_run` leaves a **self-perpetuating orphan retry timer** (sweeper re-claims every
  `lease_ttl`, no-ops on the CAS, never cancels) — folded into the deferred **run-lease + heartbeat +
  stranded-`RUNNING` reaper** ops pod (§3/S7). Documented in `sweeper.py`.
- **Durable cross-crash timeout** (detect a stage past its deadline after process death) is that same
  reaper — not in 1.2.
