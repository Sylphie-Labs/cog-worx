# Pod 4.4c-0 — pre-nightly sizing simulation + numpy fast kernel (2026-06-19/20)

> The first sub-pod of 4.4c (the Phase-4 GATE corpus). Builds the simulation that ratifies the corpus
> **size** (the F2 decision) and the machinery to run it tractably. Outcome: **F2 = E1** (corpus does
> not need to grow). The plan is `2026-06-16-pod-4.4c-plan.md`; this log records the build + the
> equivalence detour + the red-team correction.

## What it does
`sizing.py` runs a study-loop power simulation on the landed `youden.py` (`synth_cells` +
`nested_bootstrap_delta` + `power_lcb_from_studies`): for N=500 synthetic studies it counts how many
clear (paired δ-CI lower bound > 0) and takes `power_lcb_from_studies`. Certify a corpus size iff
`power_lcb ≥ 0.80` at the **pessimistic variance corner** and the **look-corrected quantile** (q=0.0025,
plumbed via the R5 additive `quantile=` kwarg on `nested_bootstrap_delta`, default-preserving + pinned).

## The performance wall and the fix (Jim-approved)
The pure-Python nested bootstrap is ~3.2 s/study at n_outer=10k → ~26 min/study-loop → ~55 hr full sweep.
A **separate numpy fast kernel** (`_sizing_fast.nested_bootstrap_delta_fast`) was built and proven
**distributionally equivalent (not byte-identical)** to the stdlib `nested_bootstrap_delta`, which stays
the live gate's sole authority (byte-identical pin untouched). **Jim signed off** on re-grounding §6.0's
"shared-code-path" guarantee from *identity* to *proven distributional-equivalence*. Architect ruled
**scorer-only** (don't port `synth_cells` — accept the Amdahl floor). numpy is the optional
`cogworx[sizing]` extra, never in the gate runtime.

## The equivalence proof, and the red-team correction
`equiv_check.py` proves the fast kernel is the same estimator via per-functional Δbar-within-MC-SE
(Gate-A) + run-spread + a mutation kill-set (M1–M5 each deliberately-broken kernel must be caught).

The first "validated" claim was **hollow**, and the red-teamer caught it:
- The cross-n "M3" leg was a **phantom** — for a scorer-only kernel there is no cross-n CRN to break
  (`synth_cells` is shared stdlib; the bootstrap streams diverge from the first draw because n_items
  differs at n=56 vs 80). The correlation gate's z=66 measured `synth_cells` study-difficulty, not the
  kernel (proven: `corr_decoup ≈ corr_shared`). **eval-stats conceded and retracted it.**
- The binding artifact was **stale** (predated the gate edits, recorded `passed:false`) and the
  run-spread gate **false-tripped the true kernel at true-null**.

Corrected, honest scope: **Gate-A (the whole proof now) + within-arm CRN (M2) + boundary gate +
structural pins.** The true-null spread false-trip was fixed with a true-null-mean carve-out (not a global
`k_spread` widening, which would blind M1). Mutant **M6** (boundary-localized index perturbation) was
added, found to be **anti-resolved** (τ→0 at scale; below the verdict's own resolution), and **retracted**
with Jim's sign-off (CF-4.4-M6; M4 covers the endpoint-index family). Binding validation re-run at
n_outer=50k × S=40 → exit 0, `passed:true`, all 4 configs + boundary, chain-of-custody verified.

## F2 decision: E1
Fast kernel is ~11× stdlib (array-allocation churn), so the full 3×3 sweep (~8 hr) was not run — the
decision is pessimistic-corner-only by design (`docs/sessions/_sizing_f2_decision.py` →
`2026-06-20-4.4c-0-sizing-F2.json`):

| cell (pessimistic, q=0.0025) | clears | power_lcb |
|---|---|---|
| n=30 | 426/500 | 0.8237 |
| n=56 | 500/500 | 0.9940 |
| n=80 | 500/500 | 0.9940 |
| true-null (n=80) | 0/500 | 0.0001 |
| under-power n=30 (planning) | 395/500 | 0.7583 |

`power_lcb(56) ≥ 0.80 ∧ power_lcb(80) ≥ 0.80` → **E1**: the 80-item/stratum budget splits **56
measurement / 24 tuning** — no +70 extra items, no budget escalation, no ABORT. The design is amply
powered even at the pessimistic corner. `true-null=0.0001` is the decisive anti-yes-machine check;
n=30 dropping below 0.80 confirms the sim discriminates (not saturated everywhere).
