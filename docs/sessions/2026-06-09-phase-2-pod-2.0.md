## Red-team (6 findings, all addressed pre-validation)

1. **HIGH — inherited `upsert_claim` back door**: blanket-SET resurrected invalidated claims and
   silently flipped `epistemic_type` (live repro). → Sealed: raises `NotImplementedError` in both
   implementations; `write_claim` is the only write surface. Attack regression-pinned.
2. **HIGH — skeleton lineage nodes**: out-of-order child-before-parent writes minted permanently
   empty `(:Claim)` nodes that crashed every read of the entity. → Coalesce-populate + skeleton
   filters on all reads; cycles now work (they require out-of-order writes).
3. **HIGH — unvalidated `base_weight`**: negative/inf weights round-tripped → confidence > 1 / NaN.
   → Type-level `gt=0` + finite; Hypothesis strategy broadened so `0 < confidence < 1` is
   guaranteed by construction, not by the test's choice of inputs.
4. **HIGH — lexicographic `as_of`**: ISO-string comparison broke under mixed timezone offsets
   (+02:00 claim invisible to a later UTC as_of) and diverged from the double. → All entity-KG
   datetimes UTC-normalized at the boundary; naive = UTC, documented; parity pinned.
5. **MED/HIGH — unnormalized identity hash**: "Has Mass" vs "has mass" split one fact across two
   nodes, halving its evidence. → `claim_id_for` normalizes components (incl. Unicode NFC);
   paraphrase dedup stays honestly with the future resolution judge.
6. **MED — sockpuppet `source_id`** (S9): 50 self-chosen source ids → confidence 0.98. → Documented
   discipline now (source_id is code-assigned, never model output); structural registry deferred —
   see carry-forwards.

Post-red-team I caught one drift the fix pass introduced: the adapter dropped a caller-set
`valid_to` at write (claim born with a known validity end) while the double honored it →
`coalesce(c.valid_to, $valid_to)` + parity regression test.
