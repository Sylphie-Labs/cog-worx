## Design (mythos — locked)

The dispatch path, end to end:

```
StructuredOutputModel.complete(messages, tools=assembled.tools)
  → ModelResponse.tool_calls
  → route_tool_calls(gate, registry, tool_calls)        # framework code (router.py)
      per call (dispatch_one):  ① check_dispatch (tier)  ② jsonschema.validate (args)
                                ③ taint.update + persist  ④ await cap.invoke (timeout)
  → tuple[ToolResult, ...] → tool_result_messages → next model round
```

- **`ToolGate`** (`capability/policy.py`) — one object, **two checkpoints + a taint latch**.
  `exposed_specs()` filters tool specs by `effective_tiers` (the model never sees a spec it can't
  call); `check_dispatch(name)` re-checks tier at call time independently (catches a forged/guessed
  name). Both read the **same** policy + taint via `effective_tiers` → cannot drift (SC-6).
- **`StageToolPolicy`** — default `allowed_tiers={read,write}` (external is NEVER ambient; Jim-approved
  posture). `external = allowed_tiers − {external}` once the drive is tainted.
- **Taint latch** — once untrusted content enters the drive, `external` is structurally removed for the
  rest of the run. Trigger is structural (`tier=="external" ∧ ¬"trusted-output"`, or `"untrusted-source"`
  tag) — never model self-report (S9). Tags are code-assigned at registration.
- **Router** (`capability/router.py`) — `dispatch_one` shared chokepoint (used by both `route_tool_calls`
  and `RunContext.dispatch`); `run_tool_loop` with a structural `ToolLoopLimit` ceiling (S11 spirit).
  Error taxonomy: `ok / invalid_args / unknown_tool / unavailable / refused_tier / error / timeout`.
- **MCP** (`capability/mcp.py`) — `bind_mcp_tools` wraps server tools as `Capability`s under namespaced
  `mcp.<server>.<tool>`, tier assigned by `MCPTierPolicy` (default **external** + `untrusted-source`
  tag) — **never** from the server's self-declared annotations (S9). Opt-in `cogworx[mcp]` extra for
  the real `StdioMCPClient` (Jim-approved); core never imports `mcp` at top level.
- **Wiring** — `RegistryToolContributor` feeds `gate.exposed_specs()` into the 3.1 tools slot at
  contribute time; engine `_build_context` mints a per-drive `ToolGate`; per-stage `bind_tool_policy`
  (concrete-only, **no StageContext Protocol break**).

Sub-pods: **3.2a** policy+gate · **3.2b** router · **3.2c** wiring · **3.2d** MCP · **3.2e** spike
(SC-1…SC-8).

## Red-team (NOT VALIDATED → fixed → VALIDATED)

First pass found **3 real S10 holes** the spike was blind to:

1. **CRITICAL — taint was not durable.** `_build_context` minted a fresh `TaintState()` every drive,
   so `resume`/`fire_timer`/`await-human`/`unpause` reset the trifecta latch to `False`. Proven
   end-to-end: pull untrusted content → `Wait` → resume → external exfil call went through. This was
   mythos's own deferred **CF-2** — **mythos revoked the deferral**: "a security guarantee that holds
   only for runs that never use the durability layer is not narrower — it is falsified," and the
   canonical Plan-Then-Execute pattern is *built on* durable boundaries.
2. **HIGH — MCP arg validation bypassable.** MCP caps registered the server's raw schema without
   `additionalProperties:false`; model-injected extra keys (`__proto__`/`admin`/`exfil`) flowed to
   `call_tool`.
3. **MEDIUM — taint latched after invoke returned**, so a fetch that side-effects then raises never
   tainted → the next external call slipped through.

### Fixes (mythos-ruled, all FIX-NOW)

1. **Durable taint** — additive S6 seam: `RunState.tainted: bool = False` + `Journal.set_run_tainted`
   (monotonic idempotent UPDATE). Written at **latch time, BEFORE invoke** (fail-closed: if the journal
   write raises, the tool is never invoked). Wired through `_build_context(tainted=...)` with
   `resume`/`_rehydrate` passing `tainted=state.tainted`; `ToolGate.persist_taint` async hook closes
   over `journal.set_run_tainted(run_id)`. **No CANON text change** — it *implements* existing S10+S6
   law (same posture as Pod 2.1's commit_xid). **Jim sign-off recorded** for the additive Journal seam.
2. **`harden_input_schema`** (`capability/schema.py`) — recursive, absence-only `additionalProperties:
   false`, shared by both the native (`registry.py`) and MCP (`mcp.py`) paths.
3. **Latch before invoke** — `dispatch_one` reordered to ①tier ②schema ③taint+persist ④invoke;
   post-invoke update deleted. A dispatch refused at ①/② does NOT taint.

Re-validation pass (2nd red-team) re-ran every exploit trace: **all 3 genuinely closed.** The trifecta
break survived no-persist, ignore-seed, taint-drops-external-off, post-invoke-latch, **multi-park across
three fresh engines**, and the fail-closed crash window. New SC-2b durable-taint spike uses a **second
Engine instance sharing only the journal** (proves the bit came from the journal, not process state).

Two LOW test-hygiene fixes applied before declaring VALIDATED (per the "no mutation-surviving assertion
in a validated spike" rule): de-vacuumed `test_build_context_tainted_true_gate_excludes_external`
(bound an external-allowing policy so taint is the only discriminator; mutation-fail confirmed); added
fail-closed `persist_taint` tests.

## Carry-forwards

- **CF-3.2-B (owner: architect)** — taint trigger is tag-dependent: an untagged **read-tier** cap
  returning attacker-controlled bytes (file/DB/RAG) does not taint. The likely fix is the inversion
  (taint unless `trusted-output`), but it re-draws the trigger table and interacts with Pod 3.4 rules —
  deferred, documented in `policy.py`. MCP (the exposed edge) already auto-tags `untrusted-source`.
- **Timescale adapter `set_run_tainted`** — not yet implemented in any `adapters/` file; fine for the
  pure-Python spike tier, **needed before Pod 3.0 live integration** uses the real Journal.
- **CF-3.1-TOKENS** — tool token accounting in provider wire format (minified-JSON under-count); xfail,
  ticketed for the integration tier against a live Claude adapter.
- **Degenerate `required`-only sub-object** not hardened by `harden_input_schema` (near-useless schema
  shape; top-level `additionalProperties:false` still guards) — hardening carry-forward.
- **SC-3 honesty edit** — the `{"path":{"$ne":None}}` case relabeled `typed_string_field_rejects_
  non_string_instance` (it is a type check, NOT an operator-injection defense).

every background agent for hangs/process pile-up. **Open infra ticket:** the spike-tier cross-test leak.
