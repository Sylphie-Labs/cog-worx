**Outcome:** Pod 1.1 complete, **CANON-COMPLIANT** (zero violations), red-team-hardened across **two**

## What landed

A 5th first-class loop transition + the durable-timer machinery on the Timescale journal (S2/S6/S8):

- **`Wait` — 5th `StageResult` kind.** `Wait(to, wake_at, output)` sits alongside
  `transition`/`done`/`await-human`/`degraded`. `_drive` splits on fresh-vs-replay: a **fresh** `Wait`
  commits the step, arms one timer keyed `f"{run_id}:{step_index}"`, sets `WAITING`, breaks; a
  **replayed** committed `Wait` cancels its timer and advances to `to` (never re-parks, never re-arms).
  `Wait.to` is a normal `StageGraph` edge — not a side channel.
- **Durable timers (lease, not delete).** `Timer` gained `timer_id` + `claimed_at`. `claim_due_timers`
  is an **atomic lease** (`UPDATE … SET claimed_at … WHERE wake_at<=now AND (claimed_at IS NULL OR
  claimed_at <= now-lease_ttl) RETURNING`), so a timer **survives** until the advance past its `Wait` is
  durably committed; a crashed lease goes stale and the next sweep re-fires it → at-least-once fire,
  exactly-once advance. (This closed the architect-flagged stuck-run hole that a destructive
  `DELETE … RETURNING` claim would have opened.)
- **Sweeper.** `runtime/sweeper.py` — `tick(now, *, lease_ttl)` leases due timers and calls
  `engine.fire_timer`; owns no model, does no commits (S1).
- **Run-level mutual exclusion (the exactly-once-*execution* fix).** Journal CAS
  `compare_and_set_run_status(expect, new)`. `fire_timer` claims `WAITING→RUNNING`, `unpause` claims
  `PAUSED→RUNNING`, and **no-op the drive if the CAS loses** — so concurrent sweepers collapse to one
  driver and a stale-lease re-delivery can't double-execute a stage. `pause` is conditional
  (`RUNNING`/`WAITING→PAUSED`, no-op on terminal) and returns `bool`.
- **Cooperative pause + uniform cleanup.** `_drive` checks authoritative `get_run_status` at each step
  boundary and breaks on `PAUSED`. Every terminal stop branch (done / terminal-degraded / ceiling-FAILED
  / **await-human**) now `cancel_timers_for_run`; `WAITING`/`PAUSED` breaks correctly keep the timer.
- **Clock on the stage context.** `RunContext`/`StageContext` now expose the engine's injected `clock`
  so a `Wait`-bearing stage computes `wake_at` without reaching for wall-clock (replay-safe).
- **Adapters at parity (S3).** Timescale (`cogworx_timers`: `timer_id` PK + `claimed_at`) and the
  in-memory double implement identical lease/cancel/CAS/get-status semantics.

## Carry-forward

- **Crashed-mid-drive auto-recovery is DEFERRED to a future ops pod** (Jim-approved). The run-status CAS
  serializes drivers but cannot tell a *live* `RUNNING` run from a *dead* one; auto-recovery needs a
  **run-lease (owner + expiry + heartbeat) + a stranded-`RUNNING` reaper**. Until then a crashed
  `RUNNING` run is recovered by an explicit `resume(run_id)` — the same gap pod 1.0 carried. Consistent
  with CANON §3/S7 (contracts-now, platform-later). Documented in the engine/journal/sweeper docstrings.
- **`unpause` of a waiting run discards the remaining sleep** (advances immediately). Documented;
  a re-park-on-unpause refinement is possible if the semantic is wanted.
- **PAUSED-timer churn:** a paused run's armed timer is re-claimed every `lease_ttl` and no-ops on the
  CAS (harmless). Optional future optimization: skip firing PAUSED runs / cancel-on-pause + re-arm.
