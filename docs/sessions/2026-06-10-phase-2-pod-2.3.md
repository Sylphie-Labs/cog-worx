## Scope (per ROADMAP)

Pod 2.3 — episodic memory + conversation capture. Synchronous cheap capture (S1 write path), episode storage and projection; async batched extraction into entity KG claims (model work strictly off-path, S1). Satisfies the S9 structural source registry precondition carried forward from Pod 2.0. Closes the 2.0 carry-forward: model-derived claims now reach the write surface only through the extraction pipeline, which uses code-registered `SourceDeclaration` objects.

## Design port and reshaping facts

1. **Turn-stamping is structural, not a direct write call** — biz-firm's `ctx.capture_episode()` on the write path would suffer the phantom-turn defect (a call that commits before commit_step records a turn that won't survive crash/replay). Embedding turns into `StepOutput.data` lets the journal commit carry them exactly-once (S6); projection happens off-path.

2. **Projection cursors split by consumer** — `EpisodeProjector` owns a PG cursor (`cogworx_projection_cursors`); `ClaimExtractor` owns a Neo4j cursor (`:ProjectionCursor` node). This parallels the 2.1 design (independent consumers, independent cursor discipline) and keeps the two phases of the pipeline orthogonal.

3. **Model work deferred off-path** — extraction happens in `ClaimExtractor`, an independent journal consumer that reads the committed journal directly (NOT `cogworx_episodes`), fires the model, and writes claims to the entity KG. The two-stage pattern mirrors 2.1's `TrialProjector` + policy-driven update: cheap structural capture, then expensive async extraction.

## Locked decisions

- **D1 — Capture = turn-stamping into step output (not a direct write call):** `stamp_turns(data, turns)` modifies `StepOutput.data` on the write path; `turns_of(step)` parses them back. A direct `EpisodeStore.append` call on the write path would write a turn for every step execution, including retried attempts — the phantom-turn defect. By embedding turns into `StepOutput.data`, the journal commit carries them exactly-once (S6); the `EpisodeProjector` sweeper then projects them into `cogworx_episodes` off-path. The phantom-turn defect is avoided structurally, not by convention.

- **D2 — Episode grain = one Turn per row:** `episode_id = f"{run_id}:{step_index}:{turn_index}"`. Table: `cogworx_episodes` (columns: `episode_id` PK, `run_id`, `step_index`, `turn_index`, `session_id`, `role`, `content`, `kind`, `occurred_at`). Rows immutable. Insert: `ON CONFLICT (episode_id) DO NOTHING`. Each episode row represents exactly one turn from a conversation.

- **D3 — `EpisodeKind` = structural Literal enum:** `"conversation"`, `"tool_exchange"`, `"system_note"` (extensible). Assigned by stage author at stamp time; no model classification on the write path. Stored as the string value in Postgres (not an integer ordinal) so schema migrations do not renumber existing rows.

- **D4 — `EpisodeProjector` sweeper:** consumes journal via `committed_steps_after(cursor)`, calls `turns_of(step)` per step, batch-inserts episodes + advances PG cursor in ONE PG transaction via `EpisodeStore.project_episodes()`. Cursor is a row in `cogworx_projection_cursors` advanced in the same txn as the episode writes. S6-additive: partial sweep = partial commit = cursor not advanced = safe to re-sweep. S8 clean: projector off → `cogworx_episodes` empty → `ClaimExtractor` idle.

- **D5 — `ClaimExtractor` is an independent journal consumer:** Reads the committed journal directly via `committed_steps_after(cursor)` (does NOT read `cogworx_episodes`); owns its own cursor (a `(:ProjectionCursor)` node in Neo4j keyed on `consumer="entity-kg/episode-extractor"`). Groups scanned steps by `session_id`, fires the model once per session group (via `render_transcript`), calls `entity_kg.project_claims()` with `SourceDeclaration`-wrapped claims. Extraction cursor lives in Neo4j; episode cursor lives in PG (D4). Independent consumers = independent failures = lesioned independently.

- **D6 — `project_claims`: ONE atomic Neo4j txn for all claims + cursor advance (D6 fixed):** `EntityKG.read_cursor(consumer)` reads from Neo4j (`:ProjectionCursor`). `EntityKG.project_claims(consumer, writes, progress=cursor)` writes all claims AND advances cursor in ONE managed Neo4j transaction. A crash leaves NO claims AND NO cursor advance — exactly-once KG state. Mirrors the 2.1 Trial-write transaction semantics.

- **D7 — Extraction minting (S9 hard walls):** 
  - `epistemic_type` hardcoded to `"inference"` (never from model output)
  - `claim.id = claim_id_for(subject, predicate, payload)` (never model-chosen; idempotent content-hash identity)
  - `source_id` from `SourceDeclaration.source_id` only (framework-minted; model output is structurally unreachable as source_id)
  - `provenance.evidence = ()` — empty tuple (the episode link lives in `source_ref`; evidence tuple is for parent claim IDs, not episodes)
  - `supporting_turn_index` validated: must be in range AND `role` must be `"user"` (v1 carries only user-turn extractions; CF-2 defers assistant/tool-turn extraction)

- **D8 — `SourceRegistry`:** `SourceDeclaration(frozen dataclass)` with deterministic `source_id = f"source:{kind}:{nfc(ref)}"`. `SourceRegistry.declare(kind, ref, *, authority)` is idempotent on identical re-declare, raises on conflicting authority. Type-level enforcement: extraction core accepts `SourceDeclaration`, not `str`. Closes the 2.0 carry-forward: model output cannot produce a `SourceDeclaration`; it produces raw text that is validated and wrapped structurally by framework code.

- **D9 — Optional embedder:** `Callable[[Sequence[str]], Awaitable[Sequence[tuple[float,...]]]] | None`. When present + latent_store present: user-turn embeddings written to latent store after claim write (off-path). Absent → skip silently (S8). Frozen in the Model contract (CF-7 deferred).

- **D10 — `EpisodeProjector` cursor in PG** (`cogworx_projection_cursors`), **`ClaimExtractor` cursor in Neo4j** (`:ProjectionCursor`). Cursor lifecycle: PG cursor is tied to the episode sweep; Neo4j cursor is tied to extraction progress. Both advance in the same transaction as their respective writes (D6 transaction, D4 transaction).

### New EvidenceType

`"extraction"`, base_weight 1.0 (F3 approved by Jim 2026-06-10). Neutral prior: extraction evidence accumulates like any other corroborating evidence; confidence derives from accumulation, not from the extraction source having special authority.

### New EntityKG seam methods (F1 approved by Jim 2026-06-10)

- `read_cursor(consumer) → ProjectionCursor | None` — read the current projection cursor for a named consumer (e.g., `"entity-kg/episode-extractor"`)
- `project_claims(consumer, writes, progress) → None` — write a batch of `ClaimProjection` objects + advance cursor in ONE managed transaction. Additive method: existing callers (`write_claim`, `upsert_claim`) unaffected. C3 rule satisfied.

## Key tensions documented

1. **Why two cursors (PG + Neo4j)?** The `EpisodeProjector` reads from the TimescaleDB journal and writes to Postgres; its cursor must live in Postgres (same transaction). The `ClaimExtractor` reads from the TimescaleDB journal directly and writes to Neo4j; its cursor lives in Neo4j (same transaction). They are independent consumers, allowing the episode and extraction phases to fail independently. This parallels the 2.1 design (independent projectors, orthogonal failure domains).

2. **Why `stamp_turns` into `StepOutput.data` instead of a direct store append?** If we appended directly to the store on the write path, a retry would create multiple episode rows for the same turn (phantom-turn defect). By embedding turns into the immutable `StepOutput.data` dict, the journal commit is the source of truth for turn existence — projection is idempotent (D2: `ON CONFLICT DO NOTHING`) and happens off-path, keeping S6 pristine.

3. **Why `SourceRegistry` instead of model-chosen source IDs?** Pod 2.0 identified structural source registry as a hard wall (S9). Until now, model output could not reach the write surface; Pod 2.3 closes this gap. `SourceRegistry.declare(kind, ref, authority)` is framework-code-only; model output produces raw text that is validated and wrapped. This is the correct structural fix, not a convention.

4. **Why is `EpisodeKind` framework-assigned, not model-inferred?** v1 requires cheap write-path capture (S1). Model-driven kind classification would either (a) run on the write path (S1 violation), or (b) require a third sweeper phase (complexity). Deferring to CF-1 keeps the v1 design lean.
