## What landed

The foundational durable-execution model (re-touched the frozen S6 journal seam, spike-gated):

- **Per-visit step keying.** `StepRecord.step_index` (monotonic per run) replaces `step_id`/
  `idempotency_key`; exactly-once is now on `(run_id, step_index)`. `_drive` replays the journaled step
  **sequence positionally**, so a stage visited N times = N distinct steps. Cyclic refine-backs work.
- **Pathway registry + cold resume.** `loop/pathway.py` `PathwayRegistry` holds code-authored,
  named/versioned `StageGraph`s ("config over code"). A run stores only the `pathway_id`+`version`
  pointer; `resume` rehydrates the graph from the registry (not in-process state) → a brand-new `Engine`
  in a fresh process resumes from Postgres alone. `self._graphs` removed.
- **Pathway fingerprint guard.** A structural fingerprint (sha256 of sorted stage names + transition
  sets + entry) is persisted at `start_run` and verified on resume — an in-place pathway edit raises
  `ResumeError` instead of silently resuming against the wrong graph. (Pure behavioral edits are caught
  by the version-bump convention.)
- **Step ceiling.** `_drive` enforces `seq < max_steps` structurally (S9/S11) → `RUN_FAILED`; a cyclic
  pathway cannot loop forever.
- **Persisted run status.** The runs record is the status authority (WAITING/PAUSED/ceiling-FAILED
  aren't derivable from a `StageResult`) — the foundation for pods 1.1/1.3.
- **TimescaleJournal:** `(run_id, step_index)` UNIQUE + `ON CONFLICT DO NOTHING`, pathway columns +
  persisted status + `set_run_status`, `read_step` by index, `reset()` DROP+recreate (schema-evolution
  robust).

## Validation (the discipline held)

- **Spike Criterion 4** (cyclic per-visit durability + cold resume) on the live Timescale journal:
  crash after the 2nd `work` visit → fresh Engine B (zero-response model, same registry) cold-resumes →
  **0 model re-calls**, two `work` steps at distinct indices [1,3], byte-equal replayed prefix.
- **Red-team** independently confirmed the load-bearing claims (cold resume reads `pathway_id` from
  Postgres, replay never recomputes, per-visit keying, ceiling sound across resume, no
  status-leads-journal window) and found one MEDIUM: the divergence guard was **untested** and
  name-only. Closed with the structural fingerprint + dedicated mutation-resistant tests for **both**
  guards (deleting either now fails a test).
- **CANON: COMPLIANT** on S1–S12, scope §3 (no operation pod built ahead), planning §4.

## Carry-forward (forward-looking notes from the reviews)

- **Event re-emit on resume.** Replayed committed steps re-emit transition/terminal events (no dedup) —
  fine now (observational broadcasts), but the S7 connecting layer will want dedup. Pod 1.1+.
- **Resume cost.** `resume` re-walks from entry replaying the whole committed prefix — O(committed
  steps) journal reads per resume. Correct (no model re-call); a perf note for the durability pods.
- **Cyclic chaos harness.** `assert_resume_never_recalls_model`'s single-crash-point shape can't target
  "the Nth visit of a stage"; a visit-counting variant could be promoted into `testing/invariants.py`
  if cyclic chaos becomes common.
