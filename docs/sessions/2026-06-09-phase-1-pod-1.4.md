## What landed

- **`RunHandle`** (new `runtime/handle.py`): thin wrapper over the backing `asyncio.Task` —
  `run_id`, `done`, `await result()`. **IN-PROCESS ONLY**, carries **no durability invariant**
  (the journal is the authority, S6); docstring names the `CancelledError` edge honestly.
- **`Engine.start()`** (`runtime/engine.py`): synchronous — validates the pathway AT THE CALL SITE
  (`PathwayError` before any task exists), refuses a **double-start** of a live run_id loud
  (`ValueError`), registers the task in a run_id-keyed registry (`_bg`, identity-checked
  eviction), then backgrounds the existing `run()` coroutine. No new model call anywhere (S1).
- **Crash feedback** (fire-and-forget-WITH-feedback, S6/S7): a new **`RUN_CRASHED`** `EventType`
  (SPINE-owned in `EVENT_BOUNDARY_MAP`) emitted from the task done-callback with
  `{error_type, error}` attributes; reading `task.exception()` there replaces asyncio's
  unreliable "never retrieved" log. The event is observational — the journal stays the authority
  (a crashed run is still RUNNING there and resumable). `_emit` gained an `attributes` param.
- **In-process drive mutex `_driving`** — THE structural fix of this pod: every drive entrypoint
  (`run`/`resume`/`fire_timer`/`unpause`/`provide_human_input`) registers the run_id for the
  duration of its drive (try/finally); `resume` of an in-flight run is a no-op; CAS entrypoints
  register BEFORE their CAS so a resume cannot slip into the CAS→drive window. Module docstring
  now scopes exactly-once honestly: in-instance = structural; cross-instance = deferred
  run-lease/reaper.
- **`aclose()`**: drain LOOP (not a one-shot snapshot) — drains tasks started mid-drain; absorbs
  exceptions only after each was surfaced via `RUN_CRASHED` + `handle.result()`.
- **Import-cycle fix** (pre-existing, detonated on this pod's entrypoint): `import cogworx.runtime`
  as the FIRST cogworx import crashed (`substrate.journal -> loop/__init__ -> stage/graph ->
  substrate.journal`). Annotation-only imports moved under `TYPE_CHECKING` in `loop/stage.py` +
  `loop/graph.py`; `tests/unit/test_import_order.py` runs 12 subprocess first-import checks.

## Validation (red-team caught three real defects before "validated")

- **Red-team findings adjudicated:** **H1 (HIGH, reproduced)** — `start()` never consulted the
  guard set: two `start()`s of one run_id = two live drivers, double model call (`start_run` is
  `ON CONFLICT DO NOTHING`, so the journal can't object), plus a set-not-refcount eviction bug.
  **H2 (HIGH, reproduced)** — pathway resolved before `start_run`: a typo'd pathway_id backgrounded
  = task dies pre-journal, `aclose` absorbs, sink mute → silently lost run; "a lost handle is never
  a lost run" was FALSE. **H3 (HIGH, reproduced)** — the start-scoped guard missed park-then-sweep
  (`fire_timer` registered nothing → concurrent resume double-drove), double-resume on one engine,
  and two-engines-one-journal (the last stays deferred: run-lease pod). **M4** — two mutants
  survived all 143 tests (one-task `aclose`, eviction deletion). **M5** — FF5b "proved" the guard
  only by deadlocking (no timeout = infinite CI hang) and its comments claimed a CAS that does not
  exist. **M6** — `aclose` docstring overclaims. **L7/L8** — vacuous handle test
  (`hasattr(cls, "__annotations__")` is true for every class), exception-contract test wrapped in
  `suppress(Exception)`. **L10** — the import cycle. **L11** — cross-engine event-id collision
  (documented in `_emit`, deferred with event dedup).
- **Fixes are structural, with named-mutant regression tests:** FF7 double-start refused ·
