## 1. What the corpus is and what it must emit

The corpus is the **ground-truth population** the arms are scored against. The model is never told the
labels or strata. Every arm run on a corpus item produces, per `(item, trial, arm)`, exactly one
`youden.Cell`; the frozen artifact is the flat list of those cells, and `nested_bootstrap_delta`
consumes it. **The label the scorer acts on IS `Cell.stratum`** — there is no separate label field, by
design (§5, §12 CRITICAL-1).

**The corpus → `Cell` mapping (binding, verified against `youden.py:50-68, 95-103, 206-208`):**

| `CorpusItem` field | → `Cell` field | Set by |
|---|---|---|
| `stratum` (`"K"` / `"O"` / `"clean"`) | `Cell.stratum` | mechanical (§2) — oracle-adjudicability, NEVER author-judged. **This is the sens/spec determinant the scorer reads.** |
| `is_error` (1 if planted/real error, 0 if re-verified clean) | (NOT a `Cell` field) | oracle / human label provenance (§3); recorded on `CorpusItem` for audit + lock + the noise-audit ε, **not** consumed by the bootstrap (the bootstrap derives error-vs-clean from `stratum`: K/O are error strata, clean is the clean stratum). |
| `error_regime` (taxonomy tag) | `Cell.regime` (R1, additive) | author at planting time, reported-only (§2.A) |
| `item_id` | `Cell.item_id` | corpus author |
| (per arm run) flag decision | `Cell.flagged` | the **arm**, at run time (4.4d) — NOT the corpus |
| (per arm run) route | `Cell.route` | the arm |
| (per arm run) trial, seed | `Cell.trial`, `Cell.seed` | the runner's CRN seeding (4.4d) |

> **Why `is_error` is not a `Cell` field (the CRITICAL-1 resolution, restated for the next reader):** the
> landed `nested_bootstrap_delta` (`youden.py:206-208`) partitions error-vs-clean **purely from
> `Cell.stratum`** and reads no label. K/O *are* the error population; clean *is* the clean population.
> A clean item is exactly an item with `stratum=="clean"`. `is_error` is therefore redundant with
> `stratum` for scoring — it lives on `CorpusItem` only for label-provenance audit and the ε bound. The
> no-leakage shuffle permutes `stratum` membership, not a phantom label (§5). This keeps the
> bootstrap's *partition logic* untouched (the shuffle adds no seam touch) — see §12 for why rev-1's
> `true_label` was a coherence hazard. **(Note: the bootstrap is no longer byte-unchanged overall — R5
> adds the additive `quantile` kwarg, §0 R5; but that is a default-preserving optional-param add, not a
> change to how it partitions error-vs-clean.)**

`flagged`/`route`/`trial`/`seed` are produced by **4.4d** (the runner), not by 4.4c. 4.4c owns
everything that is *ground truth about the item*: frame, thesis, frozen test, label + provenance,
stratum, regime, difficulty, split, and the contamination lock. The split is clean by construction:
the corpus knows truth (as `stratum` + provenance); the runner produces behavior; the scorer compares.

## 2. The mechanical stratum assignment (conforms parent §2)

An item's stratum is **oracle-determined, never author-judged** (parent §2, the CRITICAL-1 fix from the
parent's own red-team). The corpus author proposes a candidate stratum; the pipeline assigns the binding
one mechanically:

- **O** iff a registered executable oracle returns `is_executable ∧ valid_check` on the item
  (`contracts.py:120`, `EXECUTABLE_SOURCES:33`). For 4.4c's code-domain items this is: bind a
  `CodeOracle(test_source="frozen", frozen_test_code=item.test_code)`, run it against the item's thesis,
  read `valid_check ∧ is_executable`.
- **K** otherwise (no shipped oracle reaches it — oracle-blind).
- **clean** is the no-error population (`is_error == 0`); a clean item carries an O/K-style
  `oracle_reachable` bit so the C1/C2 re-verification tier is chosen correctly (§3). In `Cell` terms,
  clean items emit `stratum=="clean"` and form the shared specificity pool (`youden.py:207`).

> **Why mechanical, restated for the adversarial pass:** if the author chose the stratum, "D > A on K"
> would be measuring the author's adjudicability judgment, not the antithesis. The oracle decides; the
> author cannot move an item between strata to flatter the result. The assignment is recomputed at
> corpus-lock and stamped into the contamination hash — re-running the oracle on a different code version
> changes strata and therefore the fingerprint (§4).

### 2.A Error-regime taxonomy (gap #2 — designed, not hand-waved)

Research gap #2 ("no corpus-level error-type catalog; tess has antithesis *severity*, not this"). The
taxonomy is a **reported-only metadata column** (`Cell.regime`, R1), NOT a separately-gated stratum
(eval-stats: at n≈16/regime a per-regime δ-CI contains 0 even when the pooled effect is real — a
per-regime gate manufactures false negatives the red-team would read as "D fails on regime 2"). The
taxonomy exists to (a) make the K composition auditable, (b) enforce balanced allocation so no single
regime dominates the pooled J, and (c) report a per-regime point-estimate breakdown.

**The regimes (v1, code-domain-anchored, from the planted-error literature A5/A6/A7 + tess):**

| Regime | Description | Oracle-reachability tendency |
|---|---|---|
| `logic-wrong` | algorithm produces wrong output on valid input | usually O (a frozen test catches it) |
| `edge-case-miss` | correct on common path, wrong on boundary/empty/overflow | mixed (O if the frozen test exercises the edge, else K) |
| `spec-misread` | solves a subtly different problem than stated | usually K (oracle tests the stated problem; misread passes a naive test) |
| `silent-degradation` | plausible-but-wrong reasoning that *coincidentally* passes a weak test | K by construction (the Pod 2.1 latent-error / HIGH-3 class) |
| `off-by-semantics` | right shape, wrong units/sign/ordering convention | mixed |

**Allocation rule (the within-K composition-confound mitigation):** within the binding K, regimes are
allocated **roughly evenly** (≈ K/5 per regime) by **fixed seed**, mirroring
`tess/.../generate_claim_confidence_calibration.py`'s regime-balanced allocation. The realized regime mix
is frozen into the corpus content hash (§4) so the MeasurementFingerprint hard-refuses a silent
re-weighting. The `regime` column on `Cell` (R1) makes the mix auditable in the frozen artifact.

### 2.B Leave-one-regime-out robustness (HIGH-1 — regime mix is a hidden tuning knob)

> **HIGH-1 (red-team):** pooled-K J is composable from per-regime difficulty even with count-balance +
> content-hash. The hash freezes the mix you *chose*; difficulty-*within*-regime is unconstrained, so a
> planter can load the easy regimes with the items D happens to win and pass the pooled gate. Count
> balance does not bound this.

**Fix (non-gating but LOCK-BLOCKING, deterministic, runs on the frozen artifact) — rev-3, eval-stats Q3:**
a **leave-one-regime-out (LORO)** robustness check **plus a per-regime contribution bound**. Two parts:

1. **LORO (leave-ONE-out, kept at one — NOT leave-2-out, see the demotion below) — REPORTED-ONLY in rev-4
   (MED-D demote; was a LOCK gate in rev-3).** For each regime r, recompute the binding pooled δ-CI
   (`J_D − J_C′` and `J_D − J_A` on K) with all items of regime r dropped; **report** whether the binding
   pooled δ-CI lower bound > 0 *collapses* (lo ≤ 0) when any single regime is dropped.
   - **Why reported-only, not a lock gate (rev-4, MED-D / red-team third pass):** as a LOCK gate ("any
     single-regime collapse ⇒ refuse") this **false-refuses an HONEST corpus** with ~30% probability — when
     the binding margin is sized to *barely* clear Δmin, dropping ~16 of 80 K items can tip any one of the 5
     regimes' leave-1-out CIs below 0 by sampling noise alone, and the gate fires if *any* of the 5 does
     (≈1 − (1−p)⁵ with per-regime p≈7% ⇒ ~30%). It is a manufactured-false-refuse generator, the **same
     failure mode** that demoted leave-2-out (below) and per-regime gating (§2.A) to reported-only.
   - **The actual single-regime lock gate is part 2 (the ≤40% contribution bound), which the red-team
     confirmed has only ~2.1% honest false-refuse — sound.** LORO part-1 is logged for the reviewer; a
     collapse is a flag to inspect, not an automatic refuse.
   - **Conditional re-promotion (optional, NOT the default):** LORO part-1 MAY gate *only if* 4.4c-0 shows
     the binding margin is **comfortably above Δmin** (so a single-regime drop cannot tip an honest CI) —
     i.e. `power_lcb` at the pessimistic corner clears with healthy headroom AND the leave-1-out half-width
     inflation (≈√(80/64)=1.12) leaves the lo bound positive by construction. **The safe default is
     reported-only**; promotion is a Jim/architect call after the sim, not a build assumption.
2. **Per-regime contribution bound (the un-confounded core of HIGH-1, eval-stats Q3) — THE binding
   single-regime lock gate.** No single regime
   may contribute **> 40 %** of the pooled point-estimate δ. Compute `δ_full` (all 5 regimes) and the
   per-regime point-J on its ≈16-item subset (`_sens_spec` over each regime subset); refuse lock if any
   regime's share of the pooled effect exceeds **X = 40 %**. Rationale: with 5 evenly-allocated regimes the
   uniform share is 20 %; 40 % (2× uniform) flags a regime carrying double its fair share, while a tighter
   25 % manufactures false alarms at the ~16/regime point-estimate noise floor and a looser 60 % misses a
   genuinely loaded single regime.

> **Why NOT leave-2-out (the exact named attack — demoted, eval-stats Q3):** at n_K=80, leave-2-out leaves
> n_K≈48, widening the CI half-width by √(80/48)=1.29, and runs `C(5,2)=10` underpowered tests gating on the
> worst — **a manufactured-false-collapse generator**, the *same* failure mode that made per-regime gating
> reported-only in §2.A. Dropping a correlated, possibly difficulty-loaded 32 items makes the realized
> widening worse than the iid √-law. At this n, leave-2-out would *weaken* the gate by injecting false
> negatives, not strengthen it. The 2-regime difficulty-spread confound is therefore an **honest named
> carry-forward, CF-4.4c-LORO-2SPREAD** (§9): "LORO bounds single-regime loading only; a 2-regime spread is
> below the n=80 corpus's power to gate. Revisit at n_K≥150." The per-regime contribution bound (part 2) is
> the strongest single-regime-loading defense the n=80 corpus can carry.

Both parts' per-regime δ-CIs + contribution shares are logged. **Only a >40 % contribution (part 2) blocks
the lock** (rev-4, MED-D); **a LORO part-1 collapse is reported-only and does NOT block** (it false-refuses
honest corpora; see part 1). Neither is one of the 7 binding-core gate conditions (parent §13.5) — the
contribution bound is an instrument-validity lock gate, like the noise audit. **Both parts require the R1
`regime` field on `Cell`**
(LORO filters cells by `c.regime`; the contribution bound subsets `_sens_spec` by regime) **and rest on the
§2.A regime anti-gaming discipline (§2.C, rev-3) — without it an author defeats LORO by mis-tagging.**

> **Honesty note:** the taxonomy is code-domain; the gate's claim is code-domain dialectic. The taxonomy
> does not generalize to other domains and does not pretend to. Carried as CF-4.4c-DOMAIN (§9).

### 2.C Regime anti-author-gaming discipline (NEW-MED-1 — `regime` gates via the contribution bound, eval-stats Q7)

`stratum` is mechanically oracle-assigned (§2, un-gameable). But `regime` is author-tagged and **now gates**
(via §2.B's ≤40% per-regime contribution bound, with reported-only LORO alongside — MED-D), so an author who
mis-tags or dilutes regimes can defeat the check.
Fix — split by stratum, matching how derivable each regime is:

- **O stratum → `regime` DERIVED MECHANICALLY from the mutation operator.** The §3.5 deterministic-O
  injector already records its operator(s) in `PlanterStamp` (§4). A **fixed, code-frozen operator→regime
  table** assigns the regime: arithmetic/relational swap → `logic-wrong`; boundary/statement-deletion →
  `edge-case-miss`; constant-replacement/sign/unit → `off-by-semantics`. **Assert at lock:** every O item's
  `regime` equals the operator-derived regime; refuse lock on mismatch. This makes O-stratum regime tags as
  un-gameable as `stratum`.
- **K stratum → `regime` SECOND-AUTHOR-AUDITED** (the two oracle-blind regimes — `spec-misread`,
  `silent-degradation` — have *no* mechanical signature; that is *why* they are K and not O). The planter's
  K-regime tag is independently confirmed via the §3.4 adjudication harness (verdict ∈ {confirm-regime,
  reassign-regime, abstain}); disagreements → tie-breaker; **abstain → `regime=""`, counted in the pooled δ
  but EXCLUDED from the §2.B per-regime contribution check** (unattributable, not forced).
- **Residual (honest):** K-regime tagging remains *human-judged* (audited, not mechanical) — LORO's
  per-regime check on K is only as un-gameable as the second-author audit. Stated, folded into
  CF-4.4c-LORO-2SPREAD (§9).

## 3. The labeling pipeline — who/what sets each label

**Label-provenance rule (parent §3, non-negotiable, ratified by research A1):** every label (`is_error`,
the O/K/clean stratum) is set by **oracle or human, NEVER by any judge/antithesis model**, and never
inherited from "the run passed." An LLM may *flag* candidates for human review (§3.7) but never *set* a
label.

### 3.1 Error items — planting + label provenance

- **Planting (F3 + research A8):** error items are planted by an agent **independent of both the thesis
  and antithesis authors**, held to a **stronger independence than parent F3's "different agent"** — see
  §3.5 for the planter-independence ruling (and its honest limits).
- **Label provenance:** an error item's `is_error = 1` is provenance-stamped with `label_source:
  Literal["oracle","human"]`; for `oracle`, the frozen-`CodeOracle` invocation result (`returncode`,
  `test_provenance="frozen"`); for `human`, the adjudicator id + C2-style rationale + timestamp.
- **Info-diet stripping (port tess):** the planted item's *answer-bearing* artifacts must be stripped
  from what the antithesis sees, or the antithesis is comprehending, not predicting. Port the
  `tess/.../judge_calibration.py:161-168` `model_copy(update={experiment_design: hidden})` seam: the
  `CorpusItem` carries the full frozen test, but the **arm-input projection** (built in 4.4d) hides any
  field that names the planted error. 4.4c provides the strip-able `CorpusItem` shape + the canonical
  list of answer-bearing fields; 4.4d performs the projection (the C′-vs-D info-diet axis).

### 3.2 Clean items — C1/C2 positive re-verification (parent §3, research A3)

"It passed a Phase-1–3 run" means "wasn't caught," not "correct" (the Pod 2.1 silently-anti-conservative
gate; the 155 latent mypy errors). A latent-error item mislabeled clean turns a *good* D that flags it
into a scored false-positive — punishing the better antithesis. **Positive re-verification, two tiers:**

- **C1 (oracle-re-verified):** a `CodeOracle(test_source="frozen")` returns `holds ∧ valid_check ∧
  is_executable` — the majority. **C1 uses `test_source="frozen"`** (parent §13.4 #5 — a `thesis`-sourced
  self-test could launder a `def test(): assert True`). The frozen test is an independent author-frozen
  test, so C1 means "the corrected solution passes an independent test," not "passes its own test."
- **C2 (human-re-verified):** oracle-blind clean claims, human-adjudicated with a provenance stamp
  (adjudicator id, rationale), via the §3.4 protocol.
- The harness **refuses** to load a clean item lacking a C1 or C2 provenance stamp (the
  refuse-to-load-unlocked guard, gap #1).

### 3.3 Clean difficulty-matching (T3, eval-stats Q5) — GATED, not just reported

Trivially-clean items do not break the bootstrap math, but they **hollow out the spec arm of J**: if
every arm scores spec ≈ 1.0, then δ = J_D − J_C′ ≈ (sens_D − sens_C′) and the gate silently degenerates
to a catch-rate comparison — the yes-machine attack the whole gate exists to kill, reintroduced quietly.

> **MED-1 (red-team):** rev-1's `spec_C′ < 0.98` catches only a *perfectly trivial* pool (spec_C′=0.96
> still hollows the spec arm), and 0.98 was tuned to unverified planning variance.

**Ruling (build difficulty-matched + re-derive the tripwire from realized variance; the KS test is
DEMOTED to reported-only — eval-stats Q5 + Q8/MED-1):**

1. **Build clean items difficulty-matched by construction where cheap — the mutate-then-revert sibling
   (THIS is the real difficulty-confound control):** take a K/O error item; the clean sibling is the
   *corrected* version (same surface complexity, opposite label). The mutate-then-revert pair holds
   **surface difficulty fixed by construction** — an *item* property, not an arm output. This is also
   exactly the paired structure the sharper no-leakage control wants (§5).
2. **KS is REPORTED-ONLY, NOT a gate (rev-3, MED-1 — the difficulty proxy was circular).** rev-2 gated on a
   one-sided KS over a "difficulty proxy" = per-item flag rate. **But flag rate is an arm OUTPUT, not an
   item property** — matching "difficulty" via flag rate is circular (you match on the very thing you
   measure). **Ruling: drop the difficulty-gate pretense.** Keep the KS computation as a **reported-only
   flag-rate-distribution diagnostic** (a sanity read on whether clean and K pools produce comparable
   flag-rate distributions for the spec arm): compute per-item flag rates `p̂_i = (#flagged)/R`
   (`youden.py:101`); report the one-sided KS statistic and `D_crit = 1.22·√((n_K+n_clean)/(n_K·n_clean))`
   (≈0.19 at n=80) as a logged diagnostic. **It does not block the lock.** The matched-sibling construction
   (item 1) is the difficulty control; KS is a flag-rate-match read-out only.
3. **GATE — the spec tripwire from realized variance + a PLANNED-n design ceiling (lock precondition;
   re-derived after run-1, folded into the parent realized-Var loop §13.6).** Replace the fixed `< 0.98`:
   - a **variance floor**: `pvariance(per-item clean flag rate) ≥ 0.5 · σ²_b,spec_planning` — catches the
     spec_C′=0.96-but-hollow case (non-trivial mean spec, near-zero item-to-item variance collapses the
     bootstrap's spec spread; the mean-based 0.98 never could); and
   - a **design-derived ceiling from PLANNED n_clean, NOT realized-post-abstention n_clean (rev-3,
     NEW-MED-2, eval-stats Q8):** `realized_spec_C′ < 1 − 2/(R·n_clean_PLANNED)` (≈ 0.9964 at R=7,
     n_clean_planned=80). **Why planned, not realized:** abstention (§3.4) shrinks n_clean, which would
     *raise* the ceiling toward 1 and **loosen** the trivial-clean tripwire — exactly backwards (fewer
     clean items should make a hollow spec arm *more* suspect, not less). Fixing the ceiling at the ratified
     planning n at lock-time means abstention cannot relax it. **If realized abstention drops n_clean
     materially below planned (>20 %), that triggers the §6.0(c) re-size loop — n_clean shrinkage is handled
     by re-sizing the corpus, never by a moving ceiling.**
4. Do NOT demand exact per-item difficulty pairing for *every* clean item (over-engineering at n=80);
   match via the matched-sibling pairs (item 1) + report the flag-rate histogram + the KS diagnostic (item 2).

### 3.4 Human-adjudication protocol (gap #3 — designed)

- **Who:** ≥2 independent human adjudicators per C2-tier item and per noise-audit-flagged item; the
  architect/Jim is the tie-breaker (research A2 — frontier LLMs *flag*; humans *decide*; never
  LLM-as-authority).
- **Recorded per adjudication:** `adjudicator_id`, `verdict` (error / clean / abstain), `rationale`,
  `timestamp` — stamped into `label_provenance`.
- **Agreement measure:** report raw inter-adjudicator agreement + a **Beta-LCB on the agreement rate**
  via `cogworx.knowledge.beta.lcb` (the family `youden.power_lcb_from_studies` wraps). Disagreements go to
  the tie-breaker and are logged (the §3.7 residual-ε estimator).
- **Abstention is first-class:** an item neither adjudicator can confidently label is *dropped*, not
  forced — mirrors Pod 4.2 honest-abstention (`Thesis.verifiable_claim is None`). A forced label is
  exactly the mislabel that biases J.
- **Abstention-drop is all-cells-of-the-item (rev-3, binding — NEW-HIGH-1 / eval-stats Q5):** dropping an
  item drops **every** `(arm, trial)` cell for that `item_id`, never a partial set — else `_index_cells`
  (`youden.py:101`) leaves dangling cells that split the item across the pool (the same hazard the §5
  relabel-consistency pin guards). After all abstention-drops, the **matched-sibling pair set is
  re-validated as a clean bijection** (§5, restated): a pair `(p,q)` survives as *paired* iff **both**
  members survive; a pair with one survivor is **dissolved** and the survivor demoted to the unpaired
  global-shuffle pool carrying its real, unchanged `stratum`. This protects the §5 fixed-marginal property
  (see §5 for the proof).

### 3.5 Planter independence (research A8 — the F3 sharpening) — claim sharpened (HIGH-3)

Parent F3 says "different agent than antithesis author." Research A8: same-*model-family* circularity
(PRMBench: GPT-4o planted AND was an evaluated critic) is the real defect.

> **HIGH-3 (red-team):** "different family ∴ independent" is **necessary but not sufficient** — correlated
> pretraining = shared blind spots. The BINDING K stratum is LLM-planted; the honest fallback
> (same-family-different-instance) is *maximal* correlation. rev-1 asserted sufficiency; that is struck.

**Ruling — a two-track injector by stratum, with the sufficiency claim struck and the correlation risk
named explicitly:**

- **O stratum → deterministic / non-LLM injection preferred.** For oracle-adjudicable code errors, prefer
  **deterministic operator-based mutation** of a known-correct solution — *zero* model-family overlap with
  any arm by construction (the cleanest answer to A8). Subject to the realism cap (§3.6).
- **K stratum → different-model-family LLM injection.** Oracle-blind errors (spec-misread,
  silent-degradation) are hard to produce deterministically, so they are LLM-planted by a model from a
  **different family than both thesis and antithesis** (codebase has `ClaudeModel` + `OpenAICompatModel`
  for DeepSeek/Ollama, parent §14 decision 2). The planter family id is stamped on the item and folded
  into the MeasurementFingerprint, so planter == an evaluated arm's family is detectable.
- **Different-family is NOT asserted as sufficient.** Correlated pretraining means a different-family
  planter can still share blind spots with the antithesis. This is a residual, named risk
  (CF-4.4c-PLANTER, §9), not a closed hole.
- **Reported-diagnostic: a deterministic-injector K sub-pool (HIGH-3 collusion probe).** In addition to
  the LLM-planted K items, author a **deterministic-injector K sub-pool** (oracle-blind errors that
  *can* be produced deterministically — e.g. an off-by-semantics mutation an oracle-blind item still
  carries) so D's sensitivity is **comparable across injector kinds**. The **collusion signature** is
  reported: *D wins big on LLM-planted K but not on deterministic-K* ⇒ the LLM win may be planter↔antithesis
  correlation, not detection skill. Reported-only (not gated; it informs the §7 caveat, not the verdict).
  - **It is a ONE-DIRECTIONAL instrument (rev-3, HIGH-3 / eval-stats Q8):** a *positive* signature (D wins
    on LLM-K, **not** on deterministic-K) is informative — it surfaces correlation. A *null* result (D wins
    on **both**) is **NOT exculpatory** — absence of a collusion signature does not prove absence of
    collusion, it only fails to detect it. State this explicitly; never read a null probe as "collusion
    ruled out."
  - **Min N for the positive arm to be trusted: `n_detK ≥ 30`** (the §13.6 honest minimum). Below ~30,
    "D doesn't win on deterministic-K" is indistinguishable from sampling noise, so even the *positive*
    signature is unreliable. Size the deterministic-K sub-pool to ≥30 if its positive arm is to carry any
    weight; otherwise note the probe is purely illustrative.
- **The honest residual:** if the nightly env lacks a second family, K-planting falls back to
  same-family-different-instance, and the circularity risk for K is recorded as **not fully mitigated**
  (CF-4.4c-PLANTER) — never silently same-family. Mirrors the parent's D′ infra-contingency (decision 2):
  degrade loudly, document, do not drop.

### 3.7 Corpus noise audit (gap #4 + research A4 — the LLM-flag → human-adjudicate pass)

Research A4: ~16% raw label noise *flips rankings*; A2: the safe pattern is **LLM flags, humans decide.**
eval-stats: this is a **corpus-lock precondition, not a reported diagnostic** — a reported noise rate
annotates a corrupted J rather than fixing it, and mislabels are *signed* bias against the better
antithesis (n does not rescue a biased label set).

**The pass:**
1. **LLM-flag:** an LLM (any family — no label authority here) reviews each item's (frame, thesis, label)
   and flags suspected mislabels. A2-safe: the LLM *detects*, it does not *set*.
2. **Human-adjudicate:** every flagged item goes through §3.4; the human verdict is binding; abstentions
   drop the item.
3. **Residual-ε bound (the honest form — you cannot prove ε=0; eval-stats Q3) — SCOPE RE-STATED in rev-3
   (MED-2 / eval-stats Q6):** double-adjudicate a random subsample of the **LLM-flagged-then-adjudicated**
   items through two independent human passes; report
   `ε_hi = 1 − beta.lcb(agree+1, disagree+1, quantile=0.05)` as the **upper-95% ceiling on ADJUDICABLE
   mislabels** (those the LLM flagger surfaces for human review).
   - **What ε_hi does NOT bound (rev-3, the honest scope correction):** **flagger-correlated misses** —
     mislabels the LLM flagger systematically fails to surface — are invisible to ε_hi *by construction*
     (the subsample is conditioned on having been flagged). ε_hi is **not** a corpus-wide residual ceiling.
     Flagger-correlated misses route to **CF-4.4c-TRIANGULATION** (§9). The **unconditional** alternative
     (path b: a *pure random whole-corpus* human re-adjudication, conditioned on nothing) is strictly more
     expensive — at a low post-audit mislabel base rate the disagreement count has higher variance, so the
     expected realized subsample is **~156–207** dual-adjudications (vs the conditioned ~98), not the same
     cost — and is **deferred** (eval-stats Q6). The plan ships the *adjudicable* bound and names the
     residual; it does not pretend ε_hi is corpus-wide.
   - **Lock condition (R3, tightened to ε_hi ≤ 0.03 — was 0.05):** corpus does not lock unless
     `ε_hi ≤ 0.03`. At Δmin=0.15 with signed bias, ε ≈ 0.05 is ⅓ of the effect (red-team MED-2) — too
     loose; 0.03 keeps label-bias to ~⅕ of the effect.
   - **Subsample sizing (eval-stats Q3 — `ε_hi ≤ 0.03` must be ATTAINABLE):** solving
     `1 − beta.lcb(agree+1, disagree+1, 0.05) ≤ 0.03` against the landed `beta.lcb`:

     | observed disagreements | min subsample n (total, pooled) | ε_hi at that n |
     |---|---|---|
     | 0 | **98** | 0.0298 |
     | 1 | **156** | 0.0299 |
     | 2 | **207** | 0.0300 |

     **n is TOTAL adjudicated (pooled across strata)** — ε is a property of the labeling process; pool by
     default. If the red-team forces stratum-specific ε (plausible: clean may be easier to adjudicate),
     it becomes ~98 *per stratum*. The plan pools and states the assumption so it is attackable.
   - **Budget honesty (Jim-gated):** tightening 0.05→0.03 roughly *doubles* the dual-adjudication load
     (~58→98 best case; one disagreement → 156). **If the human budget is hard-capped below ~100,
     ε_hi ≤ 0.03 is NOT attainable and the lock must stay at 0.05 (with the signed-bias caveat
     documented).** Stated, not pretended.
4. **Fold the audited residual-ε into the MeasurementFingerprint** so a post-audit edit cannot silently
   re-lock with a stale clean bill.

### 3.9 Held-out / contamination-lock + the design-lineage look budget (gap #1 + research A9, HIGH-2; rev-3)

Research gap #1 ("no corpus-locking, git-SHA pinning, refuse-to-load-unlocked guard") and A9
(nightly-cadence feedback-loop overfitting; Ladder/Goodhart).

- **Split:** 70% **measurement** / 30% **tuning**, stratified within each of K / clean / O / regime, by
  **fixed seed**. Under R2/E2: the **80/80/70 is the measurement set**; tuning is **+~70 additional
  items** authored to a laxer bar (same-loop planting OK, no full noise audit, freely reusable). **E2 is
  conditional on the §6.0 sizing sim** (see R2).
- **`split: Literal["tuning","measurement"]`** is stamped per item, frozen into the corpus content hash.
- **The loader physically cannot load `split=="measurement"` items** during arm/prompt/diet/registry
  tuning — it filters them unless invoked with `--measurement-run` (the refuse-to-load-unlocked guard).
- **Contamination-lock = git-SHA pin:** the corpus content hash includes the git SHA at lock time; the
  scorer recomputes and hard-refuses on mismatch (the stale-artifact hole, parent §6).

> **HIGH-2 (red-team) — the rev-1 per-fingerprint touch-counter is STRUCK as the feedback-loop bound.**
> rev-1 claimed "a given fingerprint may be scored at most once ⇒ feedback-loop bound." This is **false**:
> nightly antithesis tuning mints a NEW fingerprint each night, so 30 nights of tune→re-measure on the
> *same frozen corpus* is uncorrected multiple comparisons — a null antithesis passes by selection
> (family-wise FPR = 1 − 0.95³⁰ ≈ **0.785**). The per-fingerprint counter prevents re-scoring the *same*
> system twice; it does nothing about *many different* systems against the *same* corpus.

> **HIGH-2 PARTIAL → CLOSED in rev-3 (eval-stats Q4).** The second pass found two further defects in the
> rev-2 corpus-level look-counter: **(i)** Bonferroni controls FWER only for a *pre-specified* family of K
> hypotheses, but nightly adaptive tuning chooses each night's config *after seeing* prior looks on the same
> corpus — the **garden of forking paths**, which Bonferroni does NOT cover; **(ii)** the rev-2 counter
> **resets on a forced re-roll**, so it caps looks-per-corpus, not looks-per-**design-search** — an attacker
> re-rolls to reset the budget. rev-3 fixes both: re-key the budget to **design lineage (monotone, global,
> never resets)** and separate the *within-run pre-specified* Bonferroni from the *across-night adaptive*
> bound (rotation/Ladder).

**Fix — TWO distinct corrections, never conflated (eval-stats Q4; handed to 4.4e; pure stdlib on the frozen
artifact + a durable journal ledger):**

**(A) Within ONE measurement run — Bonferroni over the PRE-SPECIFIED binding comparisons (legitimate).**
The binding core has exactly **two** pre-registered K comparisons (D>A, D>C′; parent §13.5). These are fixed
in advance, so Bonferroni is correct here: each binding δ-CI uses `quantile = 0.05/2 = 0.025` (passed via
the new `quantile` kwarg, §0 R5) — `int(0.025·n_outer)` / `int((1−0.025)·n_outer)` indices, stable at the
sim-wide n_outer≥10,000 (boundary index 250). This is **not** the feedback-loop bound; it is the standard
multiplicity correction for the 2 hypotheses scored in a single run.

**(B) Across NIGHTS / adaptive looks — a MONOTONE GLOBAL design-lineage budget, NOT a per-corpus counter
that resets.**
- **Key:** `(planning_variance_config_hash, design_lineage_chain)`, where the lineage chain is the
  **append-only list of git-SHAs of every antithesis/arm/prompt/registry config ever measured against ANY
  corpus in this design line.** `look_count = |distinct fingerprints across the whole lineage|`. **It is
  NEVER reset by a corpus re-roll *within a planning-variance config*** (a re-roll buys fresh *data*, not a
  fresh *look budget*).
  - **Honest scope of "never resets" (rev-4 downgrade, HIGH-2 / CF-4.4c-ADAPTIVE-LADDER):** the budget is
    monotone **within a `planning_variance_config_hash`**, NOT across configs. **(i)** A §6.0 re-size
    (post-run-1 realized-variance bump or the pessimistic-corner ladder) *changes*
    `planning_variance_config_hash` ⇒ a **fresh budget** for the new config — a legitimate, design-permitted
    reset, not a monotone cap over all configs. **(ii)** Lineage membership is **self-declared**: there is
    no *mechanical* parent-binding that forces a new config to inherit its predecessor's chain, so an
    operator who declares a "new" lineage starts fresh. **Cross-config monotonicity and mechanical
    lineage-parent binding are DEFERRED** (CF-4.4c-ADAPTIVE-LADDER). Do not claim an unconditional "never
    resets."
- **Where the state lives:** a durable, **append-only ledger in the TimescaleDB journal** (CANON S3/S6 — the
  journal is the right home for monotone, exactly-once-appended audit state), keyed by the design-lineage
  root. NOT in the corpus artifact (a re-roll replaces the artifact and would lose the count). The 4.4e
  scorer reads + appends; the count is exactly-once on the journal.
- **The rev-2 per-corpus content-hash counter is DEMOTED** (the same honest re-scope rev-2 applied to the
  per-fingerprint counter): it now only "prevents re-scoring one identical (system, corpus) pair twice." The
  **global lineage budget is the feedback-loop bound.**
- **Bonferroni alone is NOT a valid adaptive-FWER bound (the honest statement).** Under data-dependent
  stopping (each night's hypothesis chosen after prior looks), the honest mechanism is **fresh measurement
  data per look** — the Blum-Hardt **Ladder** (research A9): a reusable holdout survives only `~O(holdout²)`
  *adaptively-chosen* queries before overfitting. Two paths, Jim chooses (R4, §11):
  - **Path R4-a — measurement-fold ROTATION (the true adaptive bound; costs 2× measurement authoring).**
    Partition the 70 % measurement set into rotation **folds**, each itself sized to clear the §6.0 sim
    (so a 2-fold design needs **n_K≈80 per fold ⇒ ~160 measurement K items**, since a fold at n_K=40 is
    underpowered). After K_max looks against fold-1 the gate **rotates to fold-2** (fresh, never-measured
    items); when all folds are exhausted the corpus is dead → forced re-roll with **NEW authored items**,
    and **the global lineage budget is NOT reset.** Tuning (30 %) is unrotated — it is allowed to be
    Goodharted; that is its job. There is no free fresh data on a frozen corpus; rotation *banks* the
    authoring cost up front, it does not eliminate it.
  - **Path R4-b — documented Bonferroni-APPROXIMATION + global lineage cap (cheap, honestly labeled).** Keep
    the K_max=10 Bonferroni cap as a *single-fold* bound AND hard-cap the **design lineage at K_max=10 looks
    total**, then force a full re-roll (new items) with the budget consumed **globally** (no reset). Accept
    that 10 adaptive looks per design-line is the budget. **This is weaker than rotation** (Bonferroni under
    adaptivity is not a true FWER bound) and must be labeled **CF-4.4c-ADAPTIVE-LADDER**: "the across-night
    correction is a Bonferroni *approximation*; a true adaptive-data-analysis bound needs measurement-fold
    rotation (R4-a) or holdout rotation, deferred."
- **K_max=10 mechanics (apply to whichever path's per-fold/per-look Bonferroni runs, in ADDITION to the
  within-run ÷2 of (A) — i.e. the binding δ-CI tail is `0.05/(2·K_max)=0.0025` when sizing against the
  worst case; eval-stats Q2 sizes n at this corrected quantile, passed via the new `quantile` kwarg §0 R5).**
  Why K_max=10 not 30: at K=30 the tail `0.05/30≈0.00167` would put the CI endpoint at an even smaller order
  statistic, deeper into MC-instability; K=10's `0.0025` tail is the one the §6.0 sim sizes against. **The
  order-statistic stability is now bought by n_outer, not by loosening K_max:** at the 0.0025 tail
  n_outer≥10,000 puts the boundary index at `int(0.0025·10000)=25` (~20% jitter, stable; rev-4 MED-B/C —
  rev-3's n_outer=2000 → index 5 was unstable, and the ≥5000 → index 12 remedy was insufficient). If 10
  looks is too few, raise **n_outer further** (20,000 → index 50, ~14% jitter, supports a tighter tail), not
  a fancier spending function. (Bonferroni is conservative — it ignores positive correlation between
  same-corpus looks — the *correct* direction for a gate.)

> **eval-stats sized K_max against n_outer stability; α-spending (Pocock/OBF) was rejected** — those need a
> pre-planned, finite, known look-count K; opportunistic re-looks with a fresh hypothesis each night are the
> garden-of-forking-paths regime, where (within a fold) a Bonferroni cap is the clean stdlib-trivial answer
> and (across folds) **rotation** is the only honest adaptive bound. The Bonferroni-approximation path
> (R4-b) is shipped only as a *labeled* carry-forward, never claimed as a true adaptive-FWER bound.

## 5. No-leakage control: stratum-membership shuffle (parent §13.6 / eval-stats Q2) — CRITICAL-1 RESOLUTION

The gate-binding no-leakage control (parent §13.5 core condition 7). 4.4c must make the corpus shape

> **CRITICAL-1 (red-team):** rev-1 said "permute `true_label`," but the landed `nested_bootstrap_delta`

### 5.0 CRITICAL-1 RESIDUAL — the shuffle-null centering, proven (rev-3, eval-stats Q1)

> **CRITICAL-1 residual (second red-team pass):** the `|mean(shuffle_J)| < 0.05` assertion conflates
> leakage with arm-base-rate asymmetry between the paired arms — invalid for the D>A delta when arm A
> carries non-trivial K-signal.

**The red-team's specific claim is mathematically FALSE for this estimator — and proving so is the
resolution.** Against `_sens_spec:106-140` and the outer loop `nested_bootstrap_delta:212-248`: under a
stratum-membership shuffle that holds |K| and |clean| fixed with **flags welded to items**, draw a random
subset `S` of size n_K to call "K" (rest "clean"). For any single arm with per-item empirical flag rate
`f_i = (#flagged over its R trials)/R`:

- `sens_shuf = mean_{i∈S} f_i` (a flag on a "K" item scores TP — `_sens_spec:126-127`)
- `spec_shuf = 1 − mean_{i∉S} f_i` (a flag on a "clean" item scores FP — `_sens_spec:134-135`)
- **`J_shuf = sens_shuf + spec_shuf − 1 = mean_{i∈S} f_i − mean_{i∉S} f_i`** ← the load-bearing identity.

J for any single arm under the shuffle is the **difference in mean flag rate between two random halves of
the SAME pool**. Take expectation over a uniform random partition (the H0 of no label↔flag association):
with `f̄` = grand mean flag rate over all N items, `E[mean_{i∈S} f_i] = E[mean_{i∉S} f_i] = f̄`, so

> **E[J_shuf^arm] = f̄ − f̄ = 0 for EVERY arm, regardless of that arm's base flag rate.** Base rate
> cancels because relabeling moves items symmetrically between the sens-pool and the spec-pool. Hence
> `E[mean(shuffle_J_DA)] = 0 − 0 = 0` and `E[mean(shuffle_J_DC′)] = 0 − 0 = 0`. **Base-rate asymmetry does
> NOT bias the centering** — J_shuf is a *within-arm two-group contrast*, not a between-arm contrast on a
> fixed pool, which is what the red-team's critique assumed.

**The D>A degeneracy, resolved:** on the *binding* (unshuffled) scoring, A flags ≈nothing on K, so
`J_A^K ≡ 0` and `δ_DA = J_D`. But under the shuffle A is **not** identically zero — its flags are welded to
items, so `J_A_shuf = mean_{i∈S} f_i^A − mean_{i∉S} f_i^A` is a genuine (mean-zero, tiny-variance) paired
draw. So the D>A shuffle is a real paired contrast that *numerically* reduces to `≈ shuffle_J_D` (A
contributes near-zero) but is **not vacuous**. The mean-centering critique does not apply to it.

**The REAL residual the red-team should have found (and rev-3 fixes):** the threshold is an **empirical mean
over a finite number of shuffles**, not E[·]. With only 20 shuffles, MC-SE of `mean(shuffle_J)` is
`σ_shuf/√20` ≈ 0.02–0.04 for a high-variance D — so a good gate can breach 0.05 *by MC noise alone* (false
**failure**). Fix (binding): **n_shuffles ≥ 200** (MC-SE drops ~3.2× to ~0.006–0.013, making 0.05 a real
bar) AND the centering assertion becomes **CI-contains-0**, not a bare magnitude. (Pure-stdlib reshuffling
on the frozen artifact; 200 permutations × 2 deltas is cheap — no model calls.) The path stays **(a)**, NOT
a within-arm marginal-preserving permutation (that would destroy the item-difficulty structure the
matched-sibling control depends on).

**INV-A0 / INV-A1 — the mechanical corpus invariant the conditional validity rests on (refuse-to-lock).**
The centering proof holds *conditional on* arm A behaving as the floor parent §2/§13.6 assume (`sens_A≡0` on

Assert it on the **real frozen artifact** (the sizing sim scores A analytically; the gate corpus must
*earn* it):

- **INV-A0 (refuse-to-lock):** for arm A over **K cells**, `sum(flagged) == 0` — equivalently

- **INV-A1 (refuse-to-lock):** for arm A over **clean cells**, `spec_A ≥ 1 − τ_A` with

**Conditional-validity statement (write into the spike):** "The stratum-shuffle null centers at
E[δ_shuf]=0 for both D>A and D>C′ *conditional on INV-A0/INV-A1 holding on the frozen artifact* (asserted at

**The shuffle (eval-stats Q2, with the load-bearing strengthening):**
- **Permute `stratum` membership with fixed per-stratum marginal counts** (hold |K| and |clean| fixed),
  in the scorer (4.4e), on the frozen artifact. Reassign which `item_id`s carry `stratum="K"` vs
  `"clean"`; rerun the SAME `nested_bootstrap_delta` on the relabeled artifact.
- **LOAD-BEARING constraint (the thing that makes it equivalently strong to a pure-label shuffle — ship a
  mutation test):** the shuffle must **move the `stratum` field on the existing Cell records**, with each
  item's flag vectors left welded to it; it must NOT regenerate flags and must NOT carry K-flag-semantics
  with the item. The power comes from the asymmetry in `_sens_spec` (`youden.py:122-139`): on K,

  label↔flag association. **A shuffle that keeps flag-semantics attached to the item is provably weaker
  (it would preserve the association); the mutation test must make `mean(shuffle_J)` non-zero for that
  buggy variant.**
- **Implementation note (verified against `_index_cells`, `youden.py:95-103`):** the artifact indexes by

  strata and the urn sizes corrupt. Pin this.

  structure; O is reported-diagnostic anyway).
- **One permutation → one shuffled artifact → ALL deltas (eval-stats Q2).** The clean pool is shared

  between the two nulls that does not exist in the real gate (the same mistake `youden.py:18` warns against

- **`regime` travels unpermuted** — reported-only metadata; permuting it tests a null no one claims.
- **Paired sign-flip for matched siblings (the sharper control, §3.3 — restated under option (b)):** with
  no `true_label`, "flip which member of the pair is error" becomes **swap the K/clean `stratum`
  assignment within the matched pair**: for a sibling pair (item_p K, item_q clean), swap their `stratum`
  fields (and only those two), independently per pair with prob 0.5. This is a *restricted* permutation
  (within-pair, marginal counts auto-preserved) and is **strictly stronger** than the global shuffle for
  difficulty-confound control — it holds matched difficulty fixed while breaking the label binding. Same
  `model_copy(update={"stratum": ...})` shape, restricted to paired ids. **It is the PRIMARY control; the
  global stratum-shuffle is the fallback for unpaired items.**

  abstention-drop (§3.4) that orphans one member of a pair would corrupt the within-pair swap. **After all
  abstention-drops are applied to the frozen artifact, re-validate the matched-pair set as a clean
  bijection at lock, BEFORE any shuffle:** a pair `(p,q)` is retained as *paired* iff **both** survive; a
  pair with exactly one survivor is **dissolved** and the survivor **demoted to the unpaired global-shuffle
  pool carrying its real, unchanged `stratum`.** The paired sign-flip runs only over the re-validated
  bijective pairs; the global shuffle runs over the unpaired pool (orphans + never-paired items).
  - **Marginal-preservation proof (why demotion is safe):** the global shuffle holds |K| and |clean| fixed
    *over whatever pool it is given*. An orphan enters the global pool with its **real** stratum (a real K
    or real clean item), contributing +1 to the marginal it truly belongs to; the shuffle then permutes
    labels within the pool holding those (larger) marginals fixed. No marginal is corrupted because (i) the
    orphan's label was never *swapped with a dropped partner* (dissolution prevents that), and (ii) the
    global shuffle's invariant is "fixed marginals over its given pool," preserved when a real-labeled item
    is added. The orphan loses only its difficulty-matched *partner* (so it can't join the stronger paired
    control), not its label or its marginal contribution — a small power loss, not a correctness bug.
- **Assertions (rev-4, supersedes rev-3 / parent §13.6 ≥20):** **n_shuffles ≥ 200** seeded shuffles (was ≥20 — too
  few to resolve the 0.05 threshold against a high-variance D, §5.0); for EACH binding delta:
  - **(centering)** `|mean over shuffles of δ_shuf| < 0.05` **AND** the 95% interval of the shuffle-mean
    (`mean ± 1.96·sd/√n_shuffles`) **contains 0**. Failure ⇒ leakage in the *first moment* (flags track the
    label through something other than the binding the gate claims). The n_shuffles≥200 bump (§5.0) is what
    makes this assertion's MC-SE (~0.006–0.013) small enough for 0.05 to be a real bar.
  - **(coverage-RATE — rev-4, HIGH-A; REPLACES the rev-3 per-shuffle "every CI contains 0" assertion,
    which false-refused honest corpora with ~certainty).** The rev-3 form — "every individual shuffle's
    δ-CI contains 0; failure ⇒ refuse" — fails on an HONEST corpus with probability ≈ 1.0 **by
    construction:** a 95% percentile CI excludes 0 in the leakage direction ~2.5% of the time even under a
    perfect null, so over n_shuffles≥200, P(≥1 exclusion) ≈ 1 − 0.975²⁰⁰ ≈ **0.994**. It is not a leakage
    test; it is a near-guaranteed false-refuse. **Replaced by a RATE bound on the exclusion proportion
    (eval-stats this session):**
    - Count **only leakage-direction exclusions**: `k = #shuffles whose δ-CI has lo > 0` (out of
      n_shuffles). Leakage inflates δ under a label-destroying shuffle ⇒ manifests as `lo > 0`; the honest
      nominal rate is **2.5% one-sided-high** (the upper tail of the percentile CI). (`hi < 0` exclusions
      are not a leakage signature — track them as a separate diagnostic, NOT in `k`.)
    - **Refuse via a Beta 95%-UPPER bound on the exclusion rate** (computed from the landed lower-bound
      primitive by the Beta symmetry identity — no scipy, S2-clean):
      ```
      # k = #shuffles with lo > 0 ; n = n_shuffles (>=200)
      ucb95 = 1.0 - beta.lcb(n - k + 1, k + 1, quantile=0.05)   # 95% UCB on the true exclusion rate
      REFUSE corpus-lock if ucb95 > 0.08                         # CEILING = 0.08 (~2.2x the 2.5% nominal)
      ```
      Posterior `Beta(k+1, n−k+1)` (flat Beta(1,1) prior + s=k, f=n−k — the module convention). The UCB
      (not an LCB) is the right tool: it asks "could the true exclusion rate plausibly be as high as a
      leaky rate?"; an LCB>nominal test would false-refuse honest corpora whose LCB nudges past 2.5%.
    - **Calibration (binomial, n=200):** refuse triggers at roughly `k ≥ 10`. Honest (true p=0.025,
      E[k]=5, SD≈2.21): P(k≥10) ≈ 0.03 ⇒ **~3% false-refuse**. Leaky (p=0.15, E[k]=30): P(refuse) ≈ 1.0;
      even at the p=0.08 boundary k clusters at 16, well over the trigger. n_shuffles=200 cleanly separates
      2.5% honest from ≥15% leaky; it does NOT separate 2.5% from ~8% — by design, since 8% is the
      *tolerance ceiling*, not a corpus we are trying to flag.
    - **Honest caveat (state in the spike):** the 200 shuffle outcomes are NOT iid Bernoulli — they share
      the one frozen artifact, so `k`'s exclusions are positively correlated and the Beta UCB *understates*
      true uncertainty (effective n < 200); the ~3% false-refuse is a lower bound on the real rate. The
      CEILING=0.08's ~2.2× slack over nominal absorbs moderate correlation. **Report the raw observed rate
      `k/n` alongside the Beta UCB** so a reviewer sees the point estimate isn't laundered by the bound.
  - **(discrimination / mutation test — kept from rev-2):** a buggy variant that keeps K-flag-semantics
    welded to the *label* instead of the *item* must make `mean(shuffle_J)` non-zero. This proves the
    shuffle actually severs the association.
  The centering and coverage-rate assertions are **statistically orthogonal** — centering tests the first
  moment (no residual bias in the mean), coverage-rate tests the tail (no excess per-shuffle exclusions even
  if the mean cancels). A corpus can pass centering and fail coverage-rate (mean cancels but a leaky subset
  still drives lo>0 in many shuffles), so both are required; the mutation test then proves the shuffle
  actually severs the association. They fail on opposite mutations, so passing requires genuine no-leakage.

## 7. The honest external-validity statement (research T1 — drop in verbatim)

T1 is the strongest finding and the gate's biggest exposure. eval-stats: a 15–25 organic holdout is
**strictly reported-only** (cannot be gated; cannot prove the planted-vs-organic difficulty gap, which
needs n_organic ≈ 40–50 with no CRN pairing). **Decision: planted-only for v1, explicit external-validity
carry-forward + the verbatim caveat.** Sourcing 40–50 organic errors against cog-worx's thin run history
is its own project — deferred, not faked.

> The Phase-4 gate is computed on a corpus of **agent-planted** errors. A passing gate proves: *the
> adversarial dialectic (D) detects planted oracle-blind errors at a rate that beats both the oracle floor
> (A) and a neutral trajectory-equipped second look (C′), by a margin whose paired bootstrap CI excludes
> zero, without paying it back in false positives on a re-verified clean pool.* It does **NOT** prove that
> D detects **organic** (naturally-occurring) errors at the same rate. The literature (research A5: ~90% on
> synthetic vs <10% precision on real repos; 0/50 organic CVEs found by fuzzing) establishes that planted
> errors are systematically easier and more on-path than organic ones, and that performance does **not**
> reliably transfer. The planted difficulty distribution is reported (research A7); representativeness
> against the organic distribution is **unmeasured** at this gate. Organic-error external validity is an
> explicit carry-forward (**CF-4.4-ORGANIC-TRANSFER**); the planted-only gate is a *necessary* but not
> *sufficient* condition for real-world error catching.

**The correlated-blind-spot caveat (extended per the red-team — the within-corpus triangulation):** the
§7 caveat above covers *organic transfer*. It does NOT cover a distinct laundering path the four controls
**cannot** catch: a planted-K distribution correlated with BOTH the antithesis's strengths AND the LLM
noise-flagger's strengths passes ALL four controls at once (the stratum-membership shuffle, the positive
control, the noise audit, and the fingerprint) — because each control is satisfied *within* the corpus
while the corpus itself is jointly biased. This certifies a dialectic useless on organic errors,
**laundered through the controls**. Concretely: the binding K stratum is LLM-planted; if the planter, the
antithesis, and the noise-flagger share correlated pretraining, the planter writes errors the antithesis
is good at AND the flagger agrees are "real," the shuffle still collapses (the association is genuine
*within the biased corpus*), the positive control still passes (it tests the pipeline, not the corpus
bias), and the fingerprint still matches. **The deterministic-injector K collusion-probe (§3.5) is the
only within-corpus instrument that can surface this** (D wins on LLM-K but not deterministic-K), and it is
reported-only — so this triangulation is a **named, partially-instrumented residual risk, not a closed
hole.** Recorded as CF-4.4c-TRIANGULATION (§9).

**Optional cheap reported-only organic toe-hold:** IF ≤25 real cog-worx run failures can be mined cheaply,
add them as a `split="measurement"`, reported-only organic K sub-pool (point estimates only, wide
descriptive CI, **NEVER gated / NEVER counted toward external validity** — stamped in the artifact, F4).
Recommended IF cheap, deferred otherwise; does not change the binding claim either way.
