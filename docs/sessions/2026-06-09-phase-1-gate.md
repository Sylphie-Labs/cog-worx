## What landed

- **`tests/integration/test_phase1_gate_live.py`** — the gate file. Four end-to-end scenarios, each
  re-drive hop on a **FRESH `Engine`** (true cold, registry+journal rehydration), every engine on
  `ReplayModel([])` so ANY model call anywhere fails loud (the S6 no-model-on-replay and S1
  model-free-write invariants enforced at the live tier by construction):
  - **G1 (1.1):** `Wait` parks the run with a durable timer ROW in Postgres → a fresh-engine
    `Sweeper` leases + fires it → the committed `Wait` replays as an advance → COMPLETED; a second
    tick finds nothing (single delivery).
  - **G2 (1.1):** pause beats the sweeper — the fired timer's `WAITING→RUNNING` CAS loses against
    PAUSED (run stays put); a later `unpause` on another fresh engine advances past the committed
    `Wait` immediately and completes.
  - **G3 (1.2):** a flaky stage fails twice — each failure commits **nothing**, climbs the durable
    attempt counter (1 then 2, read back from live PG), parks `RETRYING` on a real backoff timer;
    each re-drive is a fresh engine's sweeper firing that timer at the **same frozen `seq`**; the
    third execution succeeds and exactly one success commit lands at `seq 0`. Three executions
    total, zero double-runs.
  - **G4 (1.4):** `start()` backgrounds a run over the live journal (via `CrashAfterStepJournal`
    wrapping it) → crashes mid-drive → `handle.result()` re-raises `SimulatedCrash` AND
    `RUN_CRASHED` lands on the event sink (the dropped-handle caller's only signal) → the live
    journal holds the committed prefix at status RUNNING → a fresh engine cold-`resume`s it to
    COMPLETED with no double-commit.
