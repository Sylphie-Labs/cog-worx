## Red-team pass (10 findings) — blockers fixed per mythos fix spec

- **F1 CRITICAL (fixed):** `ClaudeModel` structured-output returned the JSON in a `tool_use` block,
  leaving `response.text = None` → ladder native rung raised on EVERY Claude schema call. Fix: adapter
  unwraps the synthetic `_structured_output` tool call into `response.text` (the dead `_tool_call_to_text`
  helper made live) and filters it out of `tool_calls`. Ownership ruling: the ladder owns validation/
  retry; the adapter only makes `.text` carry the candidate JSON.
- **F2 HIGH (fixed):** zero-estimator default let the first over-budget USD call through. Fix:
  `BudgetGuardedModel.__init__` fails fast (`ValueError`) when `max_usd` set without an estimator;
  `build_model` supplies a conservative default estimator (`count_tokens` × `max_output_tokens` × price).
- **F3 HIGH (fixed):** `record` ran only on success → failed calls weren't counted. Fix: `start_call`
  reserves the call slot pre-call (check-then-increment, no await between → exact call ceiling under
  asyncio); `record` adds USD only, on success. Failed calls consume a slot, record no phantom USD.
- **F4 HIGH (fixed):** adapter+ladder double-mechanism — resolved by the F1 ownership ruling.
- **F5 MED (fixed):** `PriceTable` floats gained `Field(ge=0)` (negative price was poisoning the guard).
- **F7 MED (fixed):** ladder Rung-3 re-prompt no longer appends the model's unvalidated output as an
  authoritative `assistant` turn (and no empty-content turn) — single user turn quoting it as
  reference-only invalid data + the jsonschema error.
- **F9 LOW (fixed):** registry composition-order test now exercises `build_model(...)` (added a `client`
  passthrough kwarg) instead of hand-building the stack.
- **F6 / F8 / F10 (accepted as-is, documented):** factory provider-name dispatch (the one allowed S4
  seam); transport-retry token undercount; silent `json_schema` drop on a degraded adapter called
  directly (the ladder is the intended caller).
